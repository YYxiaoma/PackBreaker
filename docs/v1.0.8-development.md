# PackBreaker v1.0.8 研发文档

## 1. 版本目标

v1.0.8 以正式 v1.0.7 为升级基线，收口两个 NAS 部署与文件路径基础设施问题：

1. **彻底解除目录任务与影片去重对单一 `/data` 根的依赖。**
   用户已经显式挂载到 PackBreaker 容器中的媒体目录，例如
   `/downloads`、`/downloads2`、`/mnt/media`，应直接以容器绝对路径使用，
   不再要求重复 bind 到 `/data/...`。
2. **取消生产部署必须先以 `user: "0:0"` 启动再降权的要求。**
   推荐直接以最终 `PUID:PGID` 身份运行；`/config` 权限由宿主机明确准备，
   docker.sock 通过 supplementary group（Compose `group_add`）授权。

本版本不降低现有 preflight、inode/currentity、SHA-256、journal、原子替换、
幂等、回滚、下载器路径映射和跨设备 Hardlink 失败关闭规则。

## 2. 路径模型

### 2.1 默认命名空间根

v1.0.8 的用户路径命名空间从容器根 `/` 开始。前端/API 可以直接表达：

- `/downloads`
- `/downloads2`
- `/mnt/media/movies`

`/` 只是**浏览与命名空间根**，不是一个可以直接执行文件副作用的授权根。

### 2.2 显式挂载授权根

运行时读取 Linux `/proc/self/mountinfo`，把管理员显式挂载且为真实目录的
mountpoint 纳入任务授权根。下列区域不进入媒体任务授权范围：

- `/config`
- `/app`
- `/bin`、`/sbin`
- `/etc`
- `/dev`
- `/proc`
- `/sys`
- `/run`
- `/usr`
- `/opt`
- `/var`
- 容器根 `/`
- 默认临时根 `/tmp` 本身

显式子挂载仍以真实 mountpoint 身份判断；路径解析继续拒绝 `..`、NUL、
Windows/反斜杠混用、符号链接越界和未授权绝对路径。

### 2.3 旧任务兼容

历史数据库中已有的相对路径不迁移、不重写：

- `downloads/movies` 继续按 `PACKBREAKER_DATA_DIR`（默认 `/data`）解释；
- 新建任务选择 `/downloads/movies` 时保存绝对容器路径；
- 两种表示在 execution plan、linking、adding、client verify、seeding、
  repair、影片去重与崩溃恢复阶段均重新走同一安全路径解析。

因此 v1.0.8 不需要数据库迁移。

## 3. 功能覆盖

新的绝对挂载路径模型必须覆盖：

- 手动拆包：目录来源、文件快照与输出目录；
- 监控拆包：目录浏览、cursor 分批扫描、稳定性/防抖与断点续扫；
- 下载器来源：继续以下载器 `container_prefix` 为独立授权证据；
- execution plan：目标目录、Hardlink 文件系统检查与 downloader reverse mapping；
- linking / adding / client verifying / seeding / repair；
- 影片去重：A/B 扫描、完整 SHA-256、Hardlink/Symlink、journal、
  原子交换、恢复与最终链接校验。

跨文件系统时仍禁止 Hardlink 静默回退；只有显式允许的 Symlink 策略才可执行。
Symlink 目标使用容器真实绝对路径，例如 `/downloads/Movie.mkv`。

## 4. Docker 镜像与 `/data`

镜像继续创建普通空目录 `/data`，以兼容旧相对任务和健康检查，但 v1.0.8
不再把 `/data` 声明为 Dockerfile `VOLUME`。因此：

- 新部署不会因为镜像声明自动生成无意义的 `/data` 匿名卷；
- 用户显式挂载 `/data` 的旧部署仍正常工作；
- updater 对旧容器已存在的匿名卷仍按 inspect 结果保留，不静默丢失。

## 5. 非 root 直接运行

### 5.1 推荐模式

Compose 直接指定最终身份：

```yaml
user: "${PUID:-1000}:${PGID:-1000}"
environment:
  PUID: "${PUID:-1000}"
  PGID: "${PGID:-1000}"
```

非 root 入口：

- 不递归 chown `/config`；
- 不调用 setuid/setgid/setgroups；
- 保留 Docker/Compose 已注入的 supplementary groups；
- 校验当前 UID/GID 必须与 PUID/PGID 一致；
- 校验 `/config` 是真实目录且当前身份具备 R/W/X；
- 权限不匹配时启动失败并明确给出宿主机 `chown` 修复提示。

### 5.2 docker.sock

需要 Web 一键升级且 docker.sock GID 与 PGID 不同时：

```bash
stat -c '%g' /var/run/docker.sock
```

把该数字 GID 通过 Compose `group_add` 注入。PackBreaker 不 chmod/chown
宿主 docker.sock。Web updater 的 replacement plan 已把 `GroupAdd` 纳入
允许保留的 HostConfig 字段，升级后不会丢失附加组。

### 5.3 旧 root 入口兼容

已有 `user: "0:0"` 部署继续兼容：入口可以先修正应用专属 `/config`
所有权，再降权到 PUID/PGID。该模式不再是官方推荐默认。

## 6. 推荐 Synology Compose

```yaml
services:
  packbreaker:
    image: ghcr.io/yyxiaoma/packbreaker:latest
    container_name: packbreaker
    restart: unless-stopped
    user: "1026:100"
    ports:
      - "38000:8000"
    environment:
      PUID: "1026"
      PGID: "100"
      PACKBREAKER_TIMEZONE: "Asia/Shanghai"
    volumes:
      - /volume1/docker/packbreaker/config:/config
      - /volume2/videos/downloads:/downloads
      - /volume3/videos2/downloads:/downloads2
      - /var/run/docker.sock:/var/run/docker.sock
    # DOCKER_GID 替换为：stat -c '%g' /var/run/docker.sock
    group_add:
      - "${DOCKER_GID}"
    healthcheck:
      test: ["CMD", "python", "-m", "backend.app.healthcheck"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 20s
    security_opt:
      - no-new-privileges:true
```

首次切换为直接 UID/GID 运行前，宿主 bind 配置目录必须准备好：

```bash
sudo chown -R 1026:100 /volume1/docker/packbreaker/config
```

不使用 `chmod -R 777`。

## 7. 测试与发布门禁

必须至少覆盖：

- 授权 mount discovery 与系统/config 路径排除；
- 旧 `/data` 相对路径兼容；
- 新绝对目录浏览、任务创建和监控扫描；
- 影片去重绝对 A/B 扫描、完整 SHA-256 与最终 Hardlink/Symlink 校验；
- 未授权绝对路径、`..`、NUL、symlink 越界失败关闭；
- 非 root UID/GID 一致/不一致与 `/config` 权限错误；
- root 旧入口兼容；
- updater 保留 `User`、`GroupAdd`、docker.sock 和任意媒体 bind；
- `scripts/check.py`；
- `scripts/test.py`；
- 前端 lint/typecheck/test/build 与浏览器 prototype gate；
- AMD64/ARM64 Docker candidate、正式 v1.0.7 → v1.0.8 升级/回滚、
  updater E2E。
