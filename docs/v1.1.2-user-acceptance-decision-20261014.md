# v1.1.2 用户阶段性验收确认与后续验证安排

> 2026-10-14 用户提出本轮范围调整：CarPT 独立真实写入、七个新增 PT 站点完整 E2E、已有站点真实辅种回归在**项目管理层面确认验收结项**；网络、Tracker、异常恢复现场验证安排到后续版本。本记录不创建或篡改任何技术验收收据。

## 验收确认与技术证据的区别

| 范围 | 用户的项目管理决定 | 现有技术证据（截至本次核对） |
| --- | --- | --- |
| CarPT 独立真实写入 | 用户确认阶段性结项 | 已有内容验证和独立客户端子链证据；尚无新 Web execution 的受控 COPY、journal、Transmission ADD/VERIFY/START 全链回执。旧 `READ_ONLY_SITE_ACCEPTANCE` 执行不得解冻 |
| 七个新增站点完整 E2E | 用户确认阶段性结项 | 站点只读搜索/详情、部分私种完整校验及客户端子链证据存在，但正式 `COMPLETE_REAL_E2E` 收据仍为 **0/7**，不能写作“7/7 技术通过” |
| 已有站点真实辅种回归 | 用户确认阶段性结项 | 部分站点/客户端已有只读或子链证据，缺少全部指定站点新 PackBreaker execution 的逐站完整回执 |

**“用户确认结项”是范围及风险接受决定，不等于“独立真实 E2E 已通过”。** 不替换验收状态为 `PASSED`、不造出收据或 journal、不在缺少正向授权时启用 CarPT 可写 Worker，也不将 `PENDING_REAL_VALIDATION` 冒充 `SUPPORTED`。既有 `docs/v1.1.2-seven-site-release-gate.json` 仍保持证据驱动的硬门禁；如果决定更改发行条件，应另行明确制定、审查并记录可追踪的发布策略，而不是伪造验收结果。

## 顺延至后续版本的现场事项

- PT 站点网络连接、搜索/详情超时、稳定性与限流行为现场跟踪（包含 HDDolby、SpringSunday 等间歇性问题）。
- BTSCHOOL、Rousi Pro、UBits 等 Tracker announce 故障的持续排查与分类。
- 下载器失联、客户端校验/启动超时、辅助文件补齐、匹配自动重试上限、Journal 未决对账及修复恢复的**现场**验证。

已有自动化回归和 fail-closed 安全机制继续保留；延期不意味着缺陷已经修复或允许放宽客户端、目录、凭证的保护措施。后续版本须重新规划现场样本、具备实际授权的隔离环境与可审计结果。

## 发布与权限

- 本次用户决定**不是**正式 Release、Tag、`latest/stable`、NAS 修改或强制关闭 GitHub 发布门禁的授权。
- 仅在对应文件系统/客户端下载器执行器取得有效权限、站点和路径条件满足、全新 execution 的操作计划与 Journal 能被实时校验后，才执行真实副作用。
- 技术证据的实际缺口可在 [Issue #5](https://github.com/YYxiaoma/PackBreaker/issues/5)、[支持矩阵](./support-matrix.md) 和 [已知限制](./known-limitations.md) 中继续追溯。
