# PackBreaker v1.1.0 研发与人工验收

状态：候选研发 / 本地人工验收，未创建正式 Tag 或 Release。

发布前代码审查、版本基线、已完成门禁和仍待运行的真实 Docker/CI 门禁，统一见 [v1.1.0 发布前检查](./v1.1.0-release-readiness.md)。本文件以下逐轮记录均为历史时间点，最新执行状态以该发布前检查为准。

## 功能范围

- 数据拆包列表新增编辑、删除和失败项批量重试。批量重试仅重新排队 NO_MATCH、MATCH_TIMEOUT、MATCH_ERROR，严格检查重试策略与 If-Match 版本，不直接触发下载器写操作。
- 编辑仅作用于未来执行；既有执行配置快照不可变。选定影片任务来源、过滤与范围不可借编辑修改。删除任务需明确确认，运行中或具有外部操作 journal 的任务服务端禁止删除；无 journal 的已结束任务可删除及清理其执行历史，绝不删除源媒体。
- 全部影片都匹配失败时应为「失败」而非「部分完成」。无匹配影片支持单项重试。
- 修复限速站点只搜索首个过强查询导致的错误 NO_MATCH：优先宽松标题查询，必要时遵守站点请求间隔只读回退，保持原有内容级 FULL_VERIFIED 和人工审核安全门。
- 执行详情服务端游标分页，默认 20，可选择 50、100；页大小切换回到第一页。
- 数据去重卡片恢复「新增任务」按钮并沿用既有安全去重表单。

## 第三轮人工审核修订

- CookieCloud 增加 M-TEAM 域名族识别（浏览器可能将 Cookie 保存在 `www.m-team.cc`，而 API 配置默认 `kp.m-team.cc`）。识别后自动创建**禁用、无 API Key 的 M-TEAM 站点占位配置**，不传递浏览器 Cookie 给 M-TEAM 的 API Key 认证接口、不声称站点已可用，避免以前“站点根本不存在”的问题。仍需用户在站点管理配置真正 API Key 后人工启用。
- 系统设置页面宽度：修复 `frontend/src/details.css` 中遗留的 `.settings-content { max-width: 820px; }`，让所有子页面占满可用卡片宽度，并添加浏览器几何断言。
- 系统日志：健康存活/就绪、通知未读数和管理员会话读取的快速成功轮询不再按每次请求写 INFO。**任何 HTTP 错误、写入操作和耗时超过 1 秒的慢请求仍然记录**；Alembic 只过滤 `Context impl SQLiteImpl.` 和 `Will assume non-transactional DDL.` 两条重复的正常 INFO，不屏蔽真实迁移开始/失败信息。
- 影片匹配真实失败原因：来源影片实际 basename 为 `Hail.the.Judge.1994.BluRay.1080p.x265.10bit.2Audio.MNHD-FRDS.mkv`，目录名才包含 `九品芝麻官`。旧检索未读取父目录，曾将 Rousi 搜索结果 `The Little Death 2014` 判为年份冲突，得分 0。修复仅在父目录末尾严格匹配完整视频文件 stem 时提取中文名；再将英文片名从发布年份之前的片名段抽取，站点支持则先用有效 IMDb（及豆瓣 ID），然后英文片名、中文片名，最后带技术字段的保底查询。候选需要通过相关性初筛和年份冲突规则；任何真实辅种仍严格受种子内容校验及授权边界保护。
- Rousi 暂未验证外部 IMDb ID 查询接口，因此不能将 IMDb 号码不加区分地发送至其 `query` 参数。无正式 ID 搜索能力的站点会直接执行英文和中文标题检索。

## 第四轮：Rousi 逐查询脱敏诊断

- 仅当用户主动执行/重试匹配时，日志 `packbreaker.unpack.search_diagnostics` 按站点与搜索轮次记录阶段 `EXTERNAL_ID`、`ENGLISH_TITLE`、`CHINESE_TITLE` 或 `RELEASE_FALLBACK`；以及 `returned_count`、`reported_total`、`has_more`、`identity_filtered_count`、`title_filtered_count`、`hard_conflict_count`、`selectable_count`、`new_candidate_count`、耗时、已知的错误码和影片项 ID/候选代次。
- **绝不输出原始关键词、影片标题、API Key、Cookie、远端种子 ID 或原始响应**；不会自动访问真实站点，也不改变原有标题过滤、年份硬冲突或种子内容校验。
- 通过真实 Rousi 适配器 + 模拟 HTTP 返回的隔离回归：英文查询得到 1 个不符候选，中文查询得到 4 个候选，至少一个能进入人工审核且日志不暴露凭据。
- 已有本地失败任务 `retry_count=3` 且 `max_retries=3`，重试次数已耗尽；请在审核页自行提高该任务重试上限后再点击重试以采集**新**日志。不能将旧日志当作新增的诊断证据。

## 第五轮：匹配异常自动重试与 Rousi 过滤失效识别

- 根据真实审核日志，在一条执行中 Rousi 英文、中文及两次回退查询均返回 100 条 / 总量 8995 条，99 条标题过滤、1 条年份或身份冲突，说明搜索结果疑似未经查询关键词过滤；**这不是证明电影不存在**。对于至少两次不同查询返回同一批大型列表、总量远高于页大小且无可用候选的 Rousi 响应，标为 `SITE_SEARCH_FILTER_IGNORED_SUSPECTED`（匹配错误），缩短冗余请求，而不是误判为 `NO_MATCH`。这项异常识别并不等于已查明 Rousi 服务器忽略关键词的具体根因。
- 高级规则的「自动重试次数」仅用于系统因 **MATCH_ERROR/MATCH_TIMEOUT** 而自动排队的次数，按 2/4/8/16/30 秒退避；期间执行停留在 `MATCHING` 且无外部副作用。达到上限后才以错误/超时终态等待人工操作。纯 `NO_MATCH` 直接保留状态，不消耗自动重试预算。
- 影片项或整条任务的**人工重新匹配**不受自动重试开关、次数上限限制，人工操作开启新一轮自动重试预算（清零旧版将人工/自动重试混算的 `retry_count`），但保留候选代次及旧记录。API 乐观锁与状态检查保持不变。
- 回归包括只读真实适配器的模拟 API、同页结果过滤疑点识别、异常退避至耗尽、无匹配不消耗预算、人工重试不受自动重试规则及批量路径；仍需用户确认真实 Rousi 搜索响应行为后才能宣告匹配成功。

## 第六轮：Rousi 搜索接口根因确认及修复

- 真实只读 HTTP 对照确认：同为 `GET https://rousi.pro/api/v1/torrents?limit=20&offset=0&query=九品芝麻官`，附带 `api-token` 请求头时返回旧版 `{code:0,data:{torrents:[100],total:8995,page_size:100}}` 大列表，且英文/中文关键词均如此；**不携带任何凭据**时，公开搜索接口返回 `{items:[4],limit:20,offset:0,total:4}`，英文 `hail the judge` 则返回 3 条。这是导致匹配始终无结果的主要根因，非影片评分或站点缺失。
- 适配器明确分离协议：`/api/points/attendance/stats` 继续使用 `api-token` 检查真实 API Key；`/api/v1/torrents` 公开搜索路径只发送 `Accept: application/json`，**不发送 API Key、Cookie、Authorization 或其他用户凭据**，严格校验 `items/limit/offset/total` 和 `name/size_bytes/uploaded_at`。旧版宽泛返回 `code/data/torrents` 不再被当成成功搜索。
- 采用真实公开 Rousi 只读 URL 的适配器烟测，验证中文返回 4 条、英文返回 3 条，均具有效文件大小元数据。保留已有标题、年份和内容完整性校验；取得搜索候选不等于允许自动辅种，完整真实任务仍需用户人工验收。
