# PackBreaker v1.1.1：站点扩展与真实任务验收

## 目标与验收口径

新增 PTerClub (pterclub.net)、Audiences (audiences.me)、SpringSunday
(springsunday.net)、HDDolby (www.hddolby.com)、U2 (u2.dmhy.org)、
不可躺 (tangpt.top)、CarPT (carpt.net)。

新站点以审核过的 HTTPS origin 固定目标、Cookie 认证和 NexusPHP
只读适配器为起点。**未经过真实环境验证前全部保持
`PENDING_REAL_VALIDATION`：允许配置、CookieCloud 同步、只读连接
测试；禁止启用正式任务、取种和下载器操作。**

用户本地 CookieCloud 已含七站点 Cookie，但存在凭据不等于通过
真实连接测试，也不等于已经确认站点支持 NexusPHP 标准搜索与下载。
U2 偏动画资源，不能将《九品芝麻官》搜不到判定为接口故障。

## 双层验收

1. **七站接入验收**：运行 CookieCloud 同步，逐站记录是否导入、
   是否通过连接测试、`九品芝麻官` 的只读搜索是否有候选；确认不同域名
   的 Cookie 不串发。连接、搜索、详情、torrent 下载各阶段独立记录。
2. **原有站点拆包验收（排除 Rousi Pro）**：在本地审核实例选择已有
   《九品芝麻官》作为固定源任务，逐站做候选搜索、匹配、torrent
   元信息解析、文件映射、下载器校验、辅种提交和最终状态对账。
   已存在相同 hash 时先只读对账；不得删除/覆盖视频或盲目重复提交。
   每站记录成功、无匹配、认证失效、访问失败、元信息不兼容、
   文件不一致、下载器问题或等待人工确认。

## 安全边界

- 只读测试不调用下载器写接口；取种可能计入站点下载记录，需单独记录。
- 正式任务安全门在真实验收前不可为七个新站点解除。
- 保留 SQLite 原有站点、任务和凭证 FK 的关系，迁移需验证备份副本。
- 禁止把 Cookie、API Key、torrent payload、下载链接、用户身份或原始
  页面写入日志、Git、测试报告。

## 当前状态

- 代码已增加七站固定 Profile、通用 NexusPHP 适配器入口和新数据库迁移。
- 网络/运行时真实验收仍应依据本地审核实例实际运行结果逐站填写，不得以
  合成测试替代。

### 自动匹配候选内容校验失败后的有界回退

新增**跨正式服务的合成媒体验收**：由生产
`UnpackMatchCoordinator` 完整生成搜索结果、候选评分及入库证据，
再交给生产 `UnpackContentVerificationService`；
首选 torrent 故意设置不同的 Piece Hash，第二条使用相同影片字节。
实际执行记录为两次候选验证、首选 `MISMATCH`、
备选 `VERIFIED`、最终 `CONTENT_VERIFIED`，并核对
源文件未改变。真实生产候选的 `evidence.exact.title`、
`evidence.exact.size`、`hard_conflicts` 和
`execution.config_snapshot.matching.auto_match_threshold_bps`
均与回退判断相容，而不是只依赖手工构造的测试记录。

状态机修订：在没有下载器或文件外部副作用的内容验证阶段，
`CONTENT_VERIFYING → MATCHED_AUTO` 视为有界回退的合法转换；
不允许 `TORRENT_FETCHING`、`AUXILIARY_FETCHING`、
`CONTENT_VERIFIED`、计划/执行/做种阶段通过这条路径退回。
回退服务实际调用统一 `item_transition_allowed` 校验，
仍须满足下列候选及操作流水安全约束。

当自动选中的种子确定发生 Piece Hash 不匹配
（`UNPACK_CONTENT_MISMATCH`），或种子要求的非辅助媒体文件缺失
（`UNPACK_CONTENT_REQUIRED_FILE_MISSING`）时，允许从**同一候选代次**
中继续尝试下一条候选。必须同时满足：原匹配来源是 `AUTO`、
候选尚未验证、无硬冲突、标题和文件大小均有精确匹配证据、
评分高于本次任务自动匹配阈值、站点引用和版本结构有效。
候选按评分排序，单代次最多自动尝试 3 条。
失败候选各自的验证状态和原因保留，备选仍执行完整取种、
文件映射及 Piece Hash 验证，**绝不因换种跳过安全校验**。

若影片已有任意外部操作流水（例如先前的辅助文件下载器操作），
则**完全禁止自动换种**，以免已有副作用和新种子身份混用。
人工审核选择 `MANUAL` 不允许自动覆盖；站点超时、
认证异常或来源文件快照变化不触发回退；辅助文件待补齐
不会被当作可无条件替换候选的内容不匹配。人工并发更换候选
时，旧验证认领因当前候选和状态不一致而失效。
该策略只适用于内容校验阶段，不涉及下载器提交或回滚。
专项回归覆盖首选失败后备选真实通过、手动选择不可覆盖、
硬冲突/低分候选阻断、三次上限、站点超时不换种、
存在外部操作流水时不换种、
并发人工改选不被旧结果覆盖。

正式内容校验原先只调用 `auto_map_files(meta, (source,))`，只把
当前发现的单个影片文件作为候选。这会导致实际已具备 3 份视频文件的
多文件种子，其余两份被错误判定为非辅助媒体缺失，
即使独立全量 Piece 验收可以通过。现已修复：
`UnpackContentVerificationService` 在授权路径复查之后，
有界遍历当前影片**同一目录的直接文件**（最多 2048 个目录条目），
且只读取种子中明确列出的同名同大小普通文件的快照；
拒绝符号链接、目录越界、递归遍历及扫描上限溢出。
主文件在 torrent 抓取之后重新核验，全部映射文件在 Piece Hash
之后重新核验；任何变化不能持久化为 `FULL_VERIFIED`。
模拟的三影片多文件种子（3/3）、预存在 `.nfo` 辅助文件、
外部软链接阻断、超限目录阻断以及校验期文件替换
均已通过独立回归。本次仅修改只读内容验证，不调用真实下载器，
也不能据此将此前六站标记为真实任务做种成功。
