# PackBreaker 研发文档

本目录用于把[需求基线 v0.3](../自动拆包辅种系统-需求基线-v0.3.html)转化为可实现、可测试和可验收的研发约束。

## 文档优先级

发生冲突时按以下顺序处理：

1. 需求基线 v0.3：产品范围、安全目标和 v1.0 验收标准。
2. 本目录中的设计文档：模块接口、数据流和实现约束。
3. [AGENTS.md](../AGENTS.md)：代码、测试、凭证和交付规范。
4. README：项目概览。

设计文档不能降低需求基线中的安全门。确需改变需求时，先升级需求基线，再同步设计文档。

## 推荐阅读顺序

新参与者先阅读需求基线和系统架构，再根据工作范围阅读对应文档：

- 后端核心：领域模型 → API → 匹配与文件安全 → 测试。
- 站点/下载器接入：适配器 → API → 测试。
- 前端：API → 领域状态 → 测试中的端到端场景。
- 发布运维：部署 → 测试 → 研发路线图的 M6 门禁。

## 当前待确认输入

以下信息无法仅靠设计确定，必须在对应里程碑开始前补齐：

- 蜂巢 3.3T 大包的脱敏目录树、torrent 元数据和日志。
- 7 个失败样例及人工归因。
- HHClub 的引擎、鉴权、搜索/取种方式和自动化规则。
- 首批支持的 qBittorrent、Transmission 版本以及 NAS 路径映射。
- 使用真实语料标定的自动匹配阈值。

在真实语料完成标定前，非同 Info-hash 候选只能进入人工确认或下载器完整校验流程。

## 维护规则

- 接口、表结构、状态或安全门变化时，同一提交更新相应文档和测试计划。
- 完成一个里程碑后，在路线图中登记结论、遗留风险和下一阶段输入。
- 示例只能使用合成或完全脱敏的数据，不得提交真实 passkey、Cookie、Token、torrent 或媒体内容。
