# PackBreaker v1.0.9 研发设计

## 1. 版本目标

v1.0.9 聚焦部署体验和镜像分发，不改变任务领域模型或数据库结构。

1. 正式 Release 同时发布 GHCR 与 Docker Hub：
   - `ghcr.io/yyxiaoma/packbreaker:<version>`
   - `docker.io/yyxiaoma/packbreaker:<version>`
   - Release 资产发布并公开回读成功后，两个 Registry 才推进 `stable` / `latest`。
2. GHCR 继续作为正式 release manifest、不变 digest 和升级信任根；Docker Hub 是等价镜像源，version tag 的 manifest digest 必须与 GHCR 正式 digest 完全一致。
3. Compose 删除默认 `user:` 与 `group_add:`。用户只配置 `PUID`/`PGID`。
4. PID 1 以 root 进入极短初始化阶段，只允许：初始化 `/config`、读取 docker.sock 类型/权限/GID、设置最小 supplementary groups、`setgid(PGID)` / `setuid(PUID)`。
5. FastAPI、worker、调度器以及 Docker HEALTHCHECK 都不得以 root 身份执行。
6. 入口绝不 chmod/chown 媒体挂载或 `/var/run/docker.sock`。

## 2. Docker Hub 发布模型

GitHub Actions 需要仓库 Secrets：`DOCKERHUB_USERNAME`、`DOCKERHUB_TOKEN`。正式 Release 在镜像构建前必须确认两项非空并登录 Docker Hub；缺失凭据时失败关闭。

同一次 Buildx build 同时推送 GHCR 与 Docker Hub version tag。发布流程回读 Docker Hub version tag digest，并要求它与 `steps.build.outputs.digest` 一致。GHCR 或 Docker Hub 任一 Registry 已存在相同不可变版本 tag 时都拒绝覆盖。

`stable` / `latest` 仅在 GitHub Release 资产上传并公开回读成功后推进；推进后同时回读 GHCR 和 Docker Hub 通道 digest，任何一个不一致都使发布失败并要求人工对账。

## 3. PUID/PGID 启动模型

新部署不再声明 Docker `User` override。镜像默认 `USER root`，但应用入口必须在导入 server 前完成永久降权。默认 PUID/PGID 仍为 `1000:1000`。

显式旧式 `user: "UID:GID"` 继续兼容：此时入口发现自身已是非 root，只验证当前身份与 PUID/PGID 和 `/config` 权限，不尝试 chown 或变更 groups。

Web updater 对已有容器继续保留用户显式提供的 `User` / `GroupAdd` override，不会在升级时静默移除 Compose 自定义项。用户把 Compose 更新到 v1.0.9 推荐形式并重建后，才进入新的自动降权模型。

Docker HEALTHCHECK 单独使用 `backend.app.container_healthcheck`：若由 Docker 以 root 启动，先清空 supplementary groups，再按 PUID/PGID 降权，然后才调用实际 HTTP healthcheck。

## 4. 验收要求

- root entrypoint 只保留真实 docker.sock 所需的 supplementary GID，然后按 PUID/PGID 降权；
- 无 socket、socket 非 Unix socket、组无 RW、world RW 或 socket owner 与 PUID 相同等情况不额外保留组；
- Docker HEALTHCHECK 从 root 启动时先清空 supplementary groups，再按 PUID/PGID 降权；
- Compose 文件不含默认 `user:` / `group_add:`；
- 正式 Release workflow 同时生成 GHCR/Docker Hub version tag，且 digest 一致；
- channel sync workflow 同时修复两个 Registry 的 stable/latest；
- `release-baseline.json` 在 v1.0.9 正式发布前继续保持 v1.0.8。
