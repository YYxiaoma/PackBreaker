# PackBreaker v1.0.10 研发设计

## 1. 版本目标

v1.0.10 聚焦“减少人工前置门禁、修复 CookieCloud 同步、统一自动调度体验”，不改变既有任务执行期的安全原则。

1. 删除下载器“路径诊断”功能及其任务前置门禁。
2. 新增下载器默认启用；连接探测仍作为真实下载器操作前的必要健康证据。
3. 站点管理前端不再展示熔断状态，也不再提供“重置熔断”按钮；底层自动熔断、重试、限流保护继续保留。
4. 修复 easychen/CookieCloud 同步链，能对官方 payload 完成获取、解密、Cookie 归一化、站点匹配、凭证合并与写入。
5. CookieCloud 自动同步从固定分钟间隔改为 5 字段 Cron，复用任务中心既有 Cron 语义、项目时区与未来执行时间预览。
6. 增强 CookieCloud 可观测性，让“读取到了数据但为什么没有更新站点”能够从统计直接定位。

## 2. 下载器路径诊断移除

### 2.1 删除内容

- 删除 /api/v1/downloaders/{id}/path-diagnostics。
- 删除前端路径诊断按钮、诊断弹窗、诊断结果状态与 API/store 状态。
- 删除应用层 PathDiagnosticProbe / PathDiagnosticResult / PathDiagnosticReport 及诊断执行代码。
- 任务目标选择、执行计划生成、下载器写绑定不再要求 path_mapping_status == OK。
- 系统健康检查不再把历史路径诊断状态视为下载器异常。

数据库中的历史 path_mapping_status / last_path_diagnostic_at 列暂时保留，仅用于旧数据库迁移兼容，不再暴露到 v1.0.10 应用/API 契约，也不参与业务决策。

### 2.2 保留的执行期安全

移除“预先诊断”不等于取消路径安全。以下检查继续在真实任务链执行：

- 下载器远端路径到容器路径必须命中有效映射；
- 目标路径必须能够唯一反向映射；
- 授权根目录、路径穿越、符号链接逃逸继续拒绝；
- 文件快照、inode、设备号与硬链接跨设备限制继续由实际执行链检查；
- Transmission/qBittorrent 的真实客户端能力与连接状态继续冻结到执行绑定。

## 3. 下载器默认启用

- 新建下载器持久化默认 enabled=true。
- 前端新建成功提示明确“已创建并默认启用”。
- 新建后连接状态仍为 UNTESTED；需要真实操作时仍必须满足连接健康要求。
- 修改 base URL、类型或凭证等连接安全相关字段时，继续把连接状态重置为 UNTESTED 并停用，要求重新测试连接后再恢复使用。
- 编辑普通名称、监控规则或路径映射不再因为“路径诊断证据失效”而自动停用。

## 4. 站点熔断 UI 收口

### 4.1 用户界面

站点管理页面只展示用户真正需要的配置与连接状态：

- 不展示 circuit_state；
- 不展示“可靠性错误”；
- 不提供“重置熔断”按钮；
- store 不再维护前端 health/circuit 缓存。

### 4.2 底层保护

底层自动熔断、半开探测、失败计数、限流等待和自动恢复逻辑继续保留。只移除人工干预入口，不删除可靠性保护本身。

站点 health 只读后端能力可继续作为内部诊断/测试接口存在，但前端产品面不消费它。reset_circuit action 从公开 action 枚举删除。

## 5. CookieCloud 同步修复

集成对象固定为官方项目 easychen/CookieCloud，遵循其当前 {cookie_data, local_storage_data} 加密 payload 和 /get/:uuid 获取方式。

### 5.1 兼容修复

- Cookie 域名匹配前统一归一化：
  - 前导点；
  - 大小写；
  - 尾部点；
  - URL 形式域名，如 https://pt.example.com/；
  - 带端口/路径的可安全解析形式。
- expirationDate 缺失继续按会话 Cookie 处理。
- expirationDate=0 或负值按会话 Cookie sentinel 处理，不再误判为“已过期”。
- Cookie header 仍只向匹配站点写入，不把 CookieCloud 未支持站点数据写入 PackBreaker。
- Rousi Pro 只更新独立下载 Cookie，不覆盖其 API Key。
- 现场回归固定覆盖“CookieCloud 18 个域名组”场景：
  - 11 个当前 PackBreaker 已知站点域名必须全部可被域名归一化/匹配层识别；
  - 其中 10 个属于 CookieCloud 可更新凭据面；
  - M-TEAM 虽能识别其 CookieCloud 域名，但 PackBreaker 主凭据是 API Key，因此同步不得覆盖其 API Key。

### 5.2 同步统计

每次同步同时记录并返回：

- source_domains：CookieCloud payload 中的域名组数量；
- source_cookies：读取到的 Cookie 总数；
- eligible_sites：PackBreaker 已配置、且凭证类型允许 CookieCloud 更新的站点数；
- matched_sites：本次实际找到 Cookie 的站点数；
- updated_sites：凭证发生变化并成功写入的站点数；
- unchanged_sites：已匹配但凭证内容无变化的站点数；
- unmatched_domains：CookieCloud 中没有匹配到 PackBreaker 可同步站点的域名组数。

这样可以区分“服务端没数据”“PackBreaker 没有可同步站点”“域名匹配失败”“匹配成功但 Cookie 没变化”等情况。

## 6. CookieCloud Cron 调度

### 6.1 后端

- 新字段：sync_cron_expression，默认 */30 * * * *。
- v1.0.5-v1.0.9 的 sync_interval_minutes 数据库列保留用于降级兼容，但 v1.0.10 不再作为调度源。
- Cron 使用任务中心相同的 5 字段解析/校验逻辑。
- 自动驱动器按 PackBreaker 配置时区计算下一次命中。
- 提供 /api/v1/cookiecloud/cron-preview：
  - 规范化 Cron；
  - 返回可读描述；
  - 返回项目时区；
  - 返回未来 5 次执行时间；
  - 非法表达式返回 COOKIECLOUD_CRON_INVALID。
- 手动“立即同步”使用 force 路径，不受 Cron 调度限制。

### 6.2 前端

提供两种编辑方式：

- 图形化：每 N 分钟、每 N 小时、每天、每周、每月；
- Cron：允许用户直接填写 5 字段表达式。

编辑时实时调用后端预览，展示表达式说明、时区与未来 5 次执行时间；保存时后端再次校验，前端校验不能替代服务端判断。

## 7. 数据库迁移

新增 0034_cookiecloud_cron_v1010，基于 0033_movie_dedup_v107：

- cookiecloud_setting.sync_cron_expression
- source_domains
- source_cookies
- eligible_sites
- unchanged_sites

所有新列提供安全默认值，旧数据库升级不需要读取或修改已有站点密文，不改变现有站点配置和启停状态。

## 8. 验收要求

必须同时满足：

1. 新建下载器响应默认 enabled=true。
2. 路径诊断 API 返回 404，前端无诊断按钮/状态。
3. 未做路径诊断的下载器在连接 OK 后可以建立写绑定并参与任务目标选择。
4. 实际任务的路径越界、符号链接、映射歧义、跨设备硬链接等安全校验仍通过现有测试。
5. 站点管理前端不读取 health、不展示熔断状态、不发送 reset-circuit。
6. CookieCloud 能处理 URL 形式 domain 与 expirationDate=0 会话 Cookie。
7. CookieCloud 同步统计能准确区分 source / eligible / matched / updated / unchanged / unmatched。
8. 18 域名回归中 11 个已知站点域名全部可识别；CookieCloud 只更新 10 个允许 Cookie 写入的凭据面，M-TEAM API Key 保持不变。
9. Rousi Pro 的 API Key 在 CookieCloud 同步后保持不变，仅更新下载 Cookie。
10. Cron preview 对合法表达式返回未来 5 次执行时间，对非法表达式失败关闭。
11. 自动 CookieCloud driver 只在 Cron 到期时同步，手动 force 同步可绕过调度。
12. Alembic 从旧版本升级到 0034_cookiecloud_cron_v1010 后站点数据保持不变。
13. OpenAPI snapshot、生成 TypeScript 类型、后端静态检查、前端类型检查、Vitest 与 Python 回归测试全部通过。
