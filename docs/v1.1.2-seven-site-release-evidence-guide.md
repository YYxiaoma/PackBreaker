# v1.1.2 七站真实全链发布证据提交规范

**当前状态：七站全部待验收；当前源码禁止正式发布。** 本文档和证据清单不是验收通过的证明。

## 门禁

- 日常执行 `scripts/check.py` 只验证证据清单结构，允许如实保留待验收。
- `python scripts/validate_v112_site_release_gate.py --require-ready` 在任意一站未验收、缺少正式用户发布授权或候选源码变更后都会退出非零。当前故意失败，列明七站阻断。
- `.github/workflows/release.yml` 通过独立的 `seven-site-release-preflight` Job **最先**运行该只读离线门禁；AMD64/ARM64 发布准备、CookieCloud 上游验证均依赖其完成。`release` Job 仍保留独立二次核验。七站不全或独立发布批准缺失时，后续 Release Job 不会启动；旧版本 tag 不受这一 v1.1.2 专用检查影响。此机制不代表已触发正式发布。
- 此门禁不访问私站、下载器或媒体，不能替代逐站真实 E2E、人工核验证据、最终源码 CI、双架构镜像和升级/回滚验收。

## 七站逐一验收

固定站点：PTerClub、Audiences、SpringSunday、HDDolby、U2、TANGPT（不可躺）、CarPT。不能减少或替换其中任意一个；即使 U2 的无媒体范围历史验收已通过，也不等于此处正式全链完成。

每站只有在**同一个真实 PackBreaker Web execution** 实际完成所列步骤后，才将 `docs/v1.1.2-seven-site-release-gate.json` 的站点状态改为 `COMPLETE_REAL_E2E` 并挂载各自收据。站点收据路径固定为 `docs/v1.1.2-site-receipts/<site_key>.json`，清单里的 `receipt_sha256` 必须等于文件真实 SHA-256。

收据严格限定五个键：`site_key`（固定 ID）、`execution_id`（该站点一次真实任务的 UUID）、`source_revision`（候选代码 Git SHA）、`evidence_ref`（项目 GitHub 上已脱敏的人工可核验记录链接）、`phases`（全部阶段结果）。

`phases` 必须包含且仅包含：`identity_auth`、`search_detail`、`authorized_torrent`、`piece_hash`、`frozen_plan`、`file_materialization`、`client_verify_start`、`journal_recovery`。每一项都必须只有 `status=PASSED`、与收据相同的 `execution_id` 和可审计的 `evidence_ref`。不允许把旧种子客户端状态、独立 Piece 校验或 Mock 测试拼成一条任务，也不得造出破坏既有媒体和下载器的“成功”样本。

收据和仓库**不得**出现原始 torrent、Cookie、Passkey、API Key、Tracker 完整 URL、原始敏感 InfoHash、私人下载器连接参数或真实媒体绝对路径，只留脱敏审计标识。机器仅能核查结构与一致性，不能独立证明链接内容真实，必须另外人工审阅。

## 精确源码与发布批准

七站收据必须引用**相同候选代码 SHA**。最后一次七站验收后只允许提交这七份证据与总清单；如果应用、测试、工作流、依赖或其他文件变化，门禁会拒绝发布，必须重新收齐七站验收。

发布清单中的 `publication_approval` 默认为 `NOT_GRANTED`。只有用户明确单独授权正式发布并提供脱敏 GitHub 证据链接，才可改为 `APPROVED`；脚本不代替实际授权或 GitHub 权限审批。

另外，六旧站完整真实链、Tracker 故障、最终精确 SHA 的 CI、双架构镜像及相邻版本升级回滚仍是独立阻断，详见 `docs/v1.1.2-development.md` 和 Issue #5；七站门禁通过不等于可无条件发布。
