## 已落地能力

### Compose Web 一键升级

当前 `main` 已允许 Docker Compose 管理的 PackBreaker 容器在**显式挂载 `/var/run/docker.sock`** 时使用现有 Web 一键升级链路。

实现约束：

- 保留 Compose labels；
- 保留端口、环境变量、挂载、restart policy 与受支持的单网络配置；
- transient updater 继续保留 docker.sock，保证后续版本仍可从 Web 升级；
- `AutoRemove`、`container:<id>` namespace、多网络、显式静态 IP/MAC 等无法安全重建的拓扑继续失败关闭；
- Web updater **不会修改宿主机的 `compose.yaml`**，因此 Web 升级成功后，管理员需要同步 YAML 中的 `image:` digest，避免后续 `docker compose up -d` 按旧声明重新创建旧版本；
- 不愿授予 Docker 主机管理权限时，可以不挂载 docker.sock，继续使用宿主机 `docker compose pull && docker compose up -d` 升级。

### 发布门覆盖

- 单元测试覆盖 Compose labels 与 docker.sock 在 replacement plan 中的保留；
- `scripts/check-updater-e2e.sh` 已为 transient main container 增加 Compose labels，并在升级后检查 labels 保留；
- 新增 `Candidate Docker E2E` GitHub Actions workflow，可在不创建 tag、不发布 GHCR 正式镜像、不推进 `latest/stable` 的前提下，对当前 `main` 构建本地 candidate 镜像并运行真实 Docker updater E2E；
- workflow 支持手工 `workflow_dispatch`，同时在 `main` 的 Docker/updater/Compose 相关文件变化时自动触发；
- Candidate workflow 的通过结果属于发布前真实 Docker 证据；最终正式发布仍必须再次通过 Release workflow 的同类门禁。
- 首次 Candidate Docker E2E 已于 commit `eac1a97aa08c8f1ca617e2a909f169cd15bd5363` 上通过，workflow run `35301612491` / job `105465233475` 全绿；证据覆盖正式 v0.1.6 baseline 校验、当前 main candidate 构建、真实 helper 成功升级、unhealthy candidate 自动回滚、transient helper 容器替换、docker.sock 保留和 Compose labels 保留。
