## 尚在本地隔离验证：NexusPHP 超时分类与辅助文件恢复（未交付镜像）

- NexusPHP 适配器原将 `httpx2.TimeoutException` 与 `httpx2.NetworkError` 都映射为可重试 `SITE_UNAVAILABLE`。但匹配任务需要 `SITE_TIMEOUT` 才能在自动重试耗尽后呈现准确的超时状态；辅助文件已存在外部操作流水时，后续重试也需要保持已应用 journal。
- 独立研发工作树 `candidate/v1.1.2-nexus-timeout-20261011` 已用 SpringSunday/HDDolby 的合成 MockTransport 和辅助文件既有流水回归先红后绿：超时分类成 `SITE_TIMEOUT`，网络连接失败仍为 `SITE_UNAVAILABLE`，两者均保持可重试且不回显凭据；辅助文件已完成的外部操作仍继续对账/恢复，不重复认领。
- 只读离线候选分页验收脚本也已支持 SITE_TIMEOUT → TIMEOUT；旧 HDFans/HHClub 合成超时回归的分类契约已同步，仍要求单次只读请求、无凭据泄漏及不重试。专项先红后绿，扩展适配器/匹配/辅助任务/站点 API 通过，最终 scripts/check.py 通过，scripts/test.py 后端 **1661 passed、4 skipped、1 第三方弃用警告**，前端 **65 passed**，Vite 正式构建通过；全部为隔离测试。
- **此分类修复仅在本地研发工作树，未进入上述精确 SHA 或交付的镜像。** 不能宣称已解决 SpringSunday 实际搜索慢、HDDolby 已保存连接状态 `UNTESTED`、合法取种或正式客户端业务验收。
