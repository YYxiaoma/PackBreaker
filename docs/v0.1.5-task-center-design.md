# v0.1.5 任务中心最终设计

状态：**v0.1.5 实施基线**  
确认日期：2026-09-16

> 2026-09-17 收口范围：本文保留完整目标设计，但 v0.1.5 当前只开放已经完成 journal-backed 安全执行与真实 E2E 的能力：`VIDEO`、`HARDLINK`、保持原目录结构、`VERIFY_REUSE_OR_STOP`。压缩包/RAR 分卷、ISO、其他文件类型、软链接、复制、扁平输出及其他冲突策略属于后续执行器扩展；当前前端禁用、后端保存时拒绝，避免形成“可配置但不可执行”的假能力。Cron 已支持图形化生成与表达式两种模式，并由后端统一返回系统时区、可读说明和未来 5 次执行时间。

本文档定义 PackBreaker v0.1.5 任务中心重构的产品、交互、数据与执行约束。后续 v0.1.5 的任务中心研发以本文档为实施基线；若本文档与仓库安全约束冲突，以需求基线、`AGENTS.md` 和既有不可破坏安全门为准，不得通过降低校验、路径安全、源数据保护或幂等要求实现本文功能。

## 1. 核心模型

任务中心统一管理两类任务：

- **手动拆包任务**：用户主动选择下载器中的真实种子或本地目录中的文件，保存后立即产生一次执行。
- **监控拆包任务**：用户保存长期监控规则，由 Cron 周期性扫描下载器或目录，发现符合条件的新内容后自动产生执行。

必须区分两个层次：

### 1.1 任务定义（Task Definition）

保存任务的长期配置，包括：

- 任务名称；
- 任务类型；
- 扫描站点；
- 拆包来源；
- 下载器或目录；
- 文件过滤规则；
- Cron 调度；
- 输出目录；
- 文件存放方式；
- 冲突策略；
- 高级执行策略。

### 1.2 任务执行（Task Execution）

任务每实际运行一次都产生独立执行记录。监控任务在不同调度时间触发时必须形成不同执行记录；失败重试也必须形成新的执行记录，不能修改旧记录伪装成重新执行。

每次执行保存当时的任务配置快照，确保任务后续被编辑后仍可以还原历史执行所使用的站点、来源、过滤规则、Cron、输出目录、存放方式、冲突策略和高级设置。

## 2. 任务中心主界面

任务中心顶部保留页面标题和“新增任务”按钮，下方新增两个统计卡片：

1. **手动拆包任务**；
2. **监控拆包任务**。

两个卡片既展示统计，也作为 Tabs 快捷切换入口：

- 点击手动拆包任务卡片，切换到“手动拆包”Tab；
- 点击监控拆包任务卡片，切换到“监控拆包”Tab；
- 当前所在 Tab 对应卡片显示选中状态。

### 2.1 手动拆包统计卡片

主数字显示手动任务总数，并展示：

- 运行中；
- 等待中；
- 失败；
- 今日完成。

### 2.2 监控拆包统计卡片

主数字显示监控任务总数，并展示：

- 启用；
- 暂停；
- 异常；
- 今日触发。

## 3. 手动拆包任务列表

列表至少展示以下字段：

| 字段 | 内容 |
| --- | --- |
| 任务名称 | 用户填写，不自动生成默认名称 |
| 拆包源 | 下载器 / 目录 |
| 来源 | 下载器名称或源目录 |
| 扫描站点 | 创建任务时选择的站点 |
| 任务阶段 | 当前执行阶段 |
| 任务进度 | 百分比 + 已处理 / 总数；不能计算时显示阶段文本 |
| 任务目录 | 源目录 |
| 输出目录 | 拆包成功后的输出目录 |
| 存放方式 | 硬链接 / 软链接 / 复制 |
| 执行结果 | 成功数量 / 失败数量，可扩展跳过数量 |
| 最近执行 | 最近一次执行时间 |
| 操作 | 查看 / 执行记录 / 重试 / 复制 / 删除 |

### 3.1 执行结果

不使用单一“成功/失败”标签代替结果统计，统一展示数量，例如：

- `成功 8 · 失败 2`；
- `成功 10 · 失败 0`；
- `成功 0 · 失败 5`；
- 如存在跳过项，可显示 `成功 8 · 失败 2 · 跳过 3`。

### 3.2 重试按钮

操作列增加“重试”。默认语义是：

> 仅重试上一次执行中失败的对象，已经成功的对象不重复处理。

例如上一次执行共 10 个对象，成功 8、失败 2，点击重试后只生成包含这 2 个失败对象的新执行记录。

重试必须：

- 创建新的 `TaskExecution`；
- 标记触发方式为“失败重试”；
- 记录来源执行 ID；
- 保留原执行记录不变。

“重新执行全部”可以放入更多操作菜单，但必须二次确认。

## 4. 监控拆包任务列表

列表至少展示：

| 字段 | 内容 |
| --- | --- |
| 任务名称 | 用户填写 |
| 拆包源 | 下载器 / 目录 |
| 来源 | 下载器名称 / 监控目录 |
| 扫描站点 | 已配置站点 |
| 调度规则 | Cron 的可读说明 |
| 任务状态 | 启用 / 暂停 / 异常 |
| 当前阶段 | 等待调度 / 扫描 / 执行中 |
| 当前执行进度 | 当前执行有可计算进度时展示 |
| 最近扫描 | 最近调度时间 |
| 下次执行 | Cron 计算的下一次运行时间 |
| 最近结果 | 发现数量 / 成功数量 / 失败数量 |
| 操作 | 查看 / 执行记录 / 立即扫描 / 编辑 / 暂停 / 复制 / 删除 |

监控任务空闲时不得显示假的 `0%`，应显示“等待调度”和下次执行时间；有正在运行的执行时，再显示该执行的阶段和真实进度。

## 5. 新增任务弹窗

使用大尺寸 Modal，建议宽度 820～900px。顶部首先展示：

- 任务名称；
- 任务类型。

任务名称不生成默认值，必须由用户填写，未填写时禁止保存。

任务类型：

- 监控拆包任务；
- 手动拆包任务。

后续配置根据任务类型和拆包源动态展开，避免一次展示所有配置。

## 6. 公共配置：扫描站点

手动拆包和监控拆包都必须选择“扫描站点”。

数据来源于“站点管理”中已经配置的站点，例如 M-Team、HDTime、HHClub。下拉列表应尽量显示站点健康状态。

第一阶段一个任务选择一个扫描站点。站点暂时不可用时可以显示 Warning；站点被删除或禁用后，现有监控任务标记站点不可用并停止产生新的执行。

## 7. 监控拆包任务：执行时间

监控任务必须配置执行时间。支持两种方式：

1. 图形化时间选择；
2. Cron 表达式。

图形化模式至少支持：

- 每隔 N 分钟 / 小时；
- 每天固定时间；
- 每周；
- 每月；
- 自定义。

图形化设置最终转换为 Cron。

Cron 模式应展示：

- Cron 表达式是否合法；
- 可读解释；
- 当前 PackBreaker 系统时区；
- 未来至少 3～5 次执行时间。

## 8. 监控拆包任务：下载器来源

拆包源选择“下载器”后：

1. 展示已配置下载器下拉列表；
2. 选中下载器后展示其能力支持的匹配配置。

对于支持分类和标签的下载器，可配置：

- 分类；
- 标签；
- “满足任一条件”或“满足全部条件”。

默认开启：

- **仅处理已完成下载的种子**。

首次启用范围默认：

- **仅处理任务创建后新增的种子**。

可手动切换为“同时扫描当前已有符合条件的种子”，避免默认创建监控任务后立即处理大量历史内容。

## 9. 监控拆包任务：目录来源

拆包源选择“目录”后，通过“路径输入框 + 选择目录”组件选择监控目录。

目录浏览范围只能位于 PackBreaker 已授权的数据根目录，不能浏览 `/etc`、`/root`、`/proc` 等未授权位置。

## 10. 文件过滤规则与默认值

手动目录任务和监控目录任务复用同一套过滤规则组件，并提供适合常见拆包场景的默认值。

### 10.1 文件类型

默认：

- `视频`：**勾选**；
- `压缩包`：未勾选；
- `ISO`：未勾选；
- `其他`：未勾选。

默认视频后缀可包含：

- `.mkv`；
- `.mp4`；
- `.ts`；
- `.m2ts`；
- `.avi`；
- `.mov`；
- `.wmv`。

勾选压缩包时支持常见格式：

- `.rar`；
- `.zip`；
- `.7z`；
- `.tar`；
- `.gz`。

RAR 分卷必须识别为一个逻辑拆包对象，不能把 `.r00`、`.r01`、`.part01.rar` 等每个分卷分别创建独立任务。

### 10.2 文件大小

默认最小值和最大值都留空，即默认不限制。界面可以提供 `>100MB`、`>500MB`、`>1GB`、`>5GB` 等快捷填充，但不得作为强制默认值。

### 10.3 名称过滤

“包含名称”默认留空。

建议默认启用常见无意义媒体排除规则：

- `sample`；
- `trailer`。

用户可以删除这些默认排除项。

支持：

- 普通文本；
- 通配符；
- 正则表达式（高级模式）。

### 10.4 临时文件

默认开启“忽略临时文件”，系统级默认忽略：

- `*.part`；
- `*.tmp`；
- `*.crdownload`；
- `*.!qB`；
- `*.aria2`；
- 隐藏文件；
- 常见系统临时文件。

### 10.5 子目录

默认开启“包含子目录”，最大扫描深度默认“不限”，但后端仍必须有安全上限，防止异常目录树导致无限遍历。

## 11. 文件稳定检测

目录监控默认启用文件稳定检测，默认稳定等待时间 60 秒。

只有同时满足以下条件，文件才允许进入候选：

- 文件大小在稳定窗口内不变化；
- 修改时间在稳定窗口内不变化；
- 不是临时文件；
- 达到设置的稳定时间。

未稳定的文件本轮跳过，在后续扫描中重新检查。

## 12. 手动拆包：下载器来源

先选择已配置下载器，再展示“选择拆包种子”按钮。

点击后打开大尺寸 Drawer，不使用小弹窗嵌套小弹窗。

种子数据必须来自当前下载器中的真实种子，列表至少展示：

- 种子名称；
- 状态；
- 完成度；
- 大小；
- 分类；
- 标签；
- Tracker；
- 保存路径。

支持：

- 服务端分页；
- 搜索；
- 排序；
- 多选；
- 状态过滤；
- 分类过滤；
- 标签过滤；
- Tracker 过滤；
- 保存路径过滤。

确认后回到新增任务弹窗，显示已选择种子数量和总大小，并允许查看或重新选择。

## 13. 手动拆包：目录来源

选择目录后使用与监控任务相同的过滤规则，并提供“扫描文件”预览。

扫描完成后显示：

- 匹配文件数量；
- 总大小；
- 查看文件入口。

用户可以在文件列表中取消部分文件。最终保存时保存本次输入对象快照，避免目录内容在“预览”与“执行”之间变化造成实际处理内容偏离用户确认结果。

## 14. 拆包成功后处理

手动和监控任务共用以下设置。

### 14.1 输出目录

通过路径输入框 + 目录选择器选择拆包成功文件的目标目录。

### 14.2 存放方式

支持：

- 硬链接；
- 软链接；
- 复制。

如果源目录和目标目录位于同一文件系统并通过现有安全预检，优先默认“硬链接”。如果不支持硬链接，可自动推荐“软链接”并明确提示原因；必要时用户选择复制。

### 14.3 目录结构

默认：

- **保持原目录结构**。

可选“直接输出到目标目录”。

### 14.4 文件冲突策略

默认：

- **校验内容一致后复用，否则停止**。

其他可选：

- 跳过；
- 自动重命名；
- 覆盖。

默认不得直接覆盖已有文件。

## 15. 监控任务高级执行规则

### 15.1 去重

下载器来源至少使用 `downloader_id + torrent_hash` 作为源对象唯一身份，避免分类、标签变化或重复扫描造成重复执行。

目录来源使用规范化路径、文件大小、mtime，必要时增加文件指纹形成源对象身份；同一个稳定文件不得重复创建执行，文件真正被替换后可以识别为新的源版本。

### 15.2 扫描水位

每个监控任务维护至少：

- `last_scan_at`；
- `last_successful_scan_at`；
- `scan_checkpoint`。

应用重启后不能把所有历史文件重新当作新文件，也不能漏掉停机期间新增的数据。

### 15.3 事件冷却 / Debounce

默认冷却时间 30 秒。同一个文件在短时间内连续出现 CREATE、WRITE、RENAME、CHMOD 等事件时，只形成一个候选。

### 15.4 Cron 重叠执行

默认策略：

- **上一次仍在运行时跳过本次调度**。

可选择“上一轮结束后补执行一次”，但最多只允许一个 pending execution，禁止无限排队。

### 15.5 自动重试

默认开启可恢复错误自动重试：

- 最多 3 次；
- 第 1 次：1 分钟后；
- 第 2 次：5 分钟后；
- 第 3 次：15 分钟后。

可重试错误例如：下载器暂时不可访问、站点临时超时、网络异常、文件暂时被占用、临时 I/O 错误。

不可自动重试错误例如：RAR 分卷缺失、内容校验失败、源文件不存在、路径越界、目标冲突、硬链接不支持、任务配置错误。

### 15.6 暂停 / 恢复

暂停监控任务后：

- 不再产生新的 Cron 执行；
- 已经运行中的执行继续完成；
- 历史记录保留；
- 配置保留；
- 扫描水位保留。

恢复后从原扫描水位继续。

### 15.7 立即扫描

“立即扫描”必须复用同一套：

- 去重；
- 过滤；
- 文件稳定检测；
- 扫描水位；
- 并发控制；
- 站点安全策略。

不能因为用户手动点击而绕过安全规则。

### 15.8 克隆任务

克隆以下配置：

- 任务类型；
- 扫描站点；
- 下载器 / 目录；
- 过滤规则；
- Cron；
- 输出设置；
- 高级设置。

不克隆：

- 任务名称；
- 执行记录；
- 扫描水位；
- 错误状态；
- 最近运行状态。

克隆后任务名称保持空白，由用户重新填写。

### 15.9 删除任务

删除监控任务前确认是否保留历史执行记录，默认保留。删除任务后不得再产生新的调度执行。

## 16. 执行阶段与进度

建议统一阶段枚举：

- `WAITING`：等待执行；
- `DISCOVERING`：发现源数据；
- `ANALYZING`：分析文件；
- `SCANNING_SITE`：扫描站点；
- `PREPARING`：准备拆包；
- `UNPACKING`：正在拆包；
- `OUTPUTTING`：写入输出；
- `VERIFYING`：验证结果；
- `COMPLETED`：已完成；
- `FAILED`：失败；
- `SKIPPED`：已跳过。

进度展示至少包含：

- 当前阶段；
- 总体百分比（只有能真实计算时才显示）；
- 已处理对象数；
- 总对象数；
- 当前对象。

无法准确计算某阶段百分比时只显示“正在扫描站点…”等阶段文本，不得制造假的百分比。

## 17. 任务详情

点击任务名称或“查看”进入任务详情页。顶部展示任务状态和常用操作，主体至少包含三个 Tabs：

1. 概览；
2. 配置；
3. 执行记录。

概览展示：

- 扫描站点；
- 来源；
- 调度规则；
- 下次执行；
- 最近执行结果；
- 当前状态。

监控任务提供“暂停”“立即扫描”“编辑”等操作。

## 18. 执行记录列表

执行记录至少展示：

| 字段 | 内容 |
| --- | --- |
| 执行时间 | 开始时间 |
| 触发方式 | Cron / 立即扫描 / 手动任务 / 失败重试 / 系统恢复 |
| 扫描结果 | 发现多少对象 |
| 成功 | 成功数量 |
| 失败 | 失败数量 |
| 跳过 | 跳过数量 |
| 状态 | 完成 / 部分失败 / 失败 |
| 耗时 | 总运行时间 |
| 操作 | 查看 / 重试失败对象 |

支持按状态、触发方式、时间范围、源文件/种子名称搜索过滤。

## 19. 执行记录详情

点击一条执行记录打开 Drawer，展示：

- 执行 ID；
- 任务名称；
- 状态；
- 触发方式；
- 开始 / 结束时间；
- 耗时；
- 扫描站点；
- 成功数量；
- 失败数量；
- 跳过数量；
- 来源执行 ID（如为重试）。

### 19.1 执行时间线

时间线以结构化事件展示一次执行实际发生的过程，例如：

- 开始执行；
- 读取下载器；
- 找到符合规则的对象；
- 去重；
- 扫描站点；
- 创建拆包计划；
- 开始拆包；
- 写入输出；
- 验证失败；
- 执行结束。

### 19.2 执行对象列表

每个种子 / 文件对象至少展示：

- 名称；
- 来源；
- 大小；
- 阶段；
- 进度；
- 结果。

对象详情继续展示源路径、扫描站点、匹配结果、拆包文件数量、输出文件数量、输出目录和存放方式。

### 19.3 失败信息

失败对象至少记录：

- 稳定错误代码；
- 失败阶段；
- 中文错误摘要；
- 技术详细信息；
- 是否可重试；
- 已重试次数。

## 20. 日志语言与展示规范

底层日志不直接把所有内容硬编码为中英文混合字符串。推荐采用：

> **结构化英文事件代码 + 英文技术信息 + UI 中文映射**。

日志结构至少支持：

- `event_code`；
- `message`；
- `task_id`；
- `execution_id`；
- `trace_id`；
- 结构化上下文。

例如底层记录：

```text
event_code = TASK_UNPACK_STARTED
message = Unpack operation started
```

前端根据 `TASK_UNPACK_STARTED` 映射中文“开始拆包”，日志中心最终显示：

```text
开始拆包
Unpack operation started
```

或者紧凑显示为：

```text
开始拆包 · Unpack operation started
```

这样可以同时保证：

- 用户中文可读性；
- 稳定机器错误码；
- 英文技术上下文；
- 搜索和过滤能力；
- 自动化测试稳定性；
- 后续修改中文文案不影响底层日志解析。

### 20.1 未知事件

如果前端尚未提供某个 `event_code` 的中文映射，必须保留英文原始信息，并显示“未翻译事件”，不能隐藏日志。

### 20.2 执行记录与日志联动

执行详情中的“查看日志”跳转到日志中心时，自动携带：

- `task_id`；
- `execution_id`；
- `trace_id`；
- 对应时间范围。

用户不需要再手工搜索整套日志。

## 21. 保存前统一预检

新增或编辑任务保存前至少检查：

- 任务名称；
- 扫描站点；
- 下载器连接；
- 目录访问权限；
- Cron；
- 过滤规则；
- 源目录；
- 目标目录；
- 文件系统关系；
- 硬链接能力；
- 冲突策略。

检查结果分为：

- `OK`：正常；
- `WARNING`：用户确认后可以保存；
- `BLOCKED`：禁止保存。

## 24. 推荐数据模型

v0.1.5 实现时建议以以下模型分层：

- `TaskDefinition`：长期任务定义；
- `TaskSchedule`：Cron 与调度状态；
- `TaskSource`：下载器 / 目录来源；
- `TaskFilter`：过滤规则；
- `TaskOutputPolicy`：输出目录、存放方式、冲突策略；
- `TaskExecutionPolicy`：去重、重叠、自动重试、稳定检测等；
- `TaskExecution`：一次任务运行；
- `TaskExecutionItem`：本次运行中的单个种子 / 文件对象；
- `TaskExecutionEvent`：执行时间线中的结构化事件。

该模型必须兼容现有 task/task_unit、预演、审核、执行计划、operation journal 和安全执行链，不能通过绕开既有证据链来实现新 UI。

## 26. 最终产品层次

任务中心最终形成三个纵向层次：

1. **任务中心**：系统有哪些任务，整体运行情况如何；
2. **任务定义**：任务什么时候运行、从哪里取数据、扫描哪个站点、什么内容需要拆包、结果输出到哪里；
3. **执行记录**：某一次实际处理了多少内容，成功多少、失败多少，在哪一步失败，是否可以重试。

日志中心作为横向诊断能力，回答：

> 某次执行在技术层面实际发生了什么。

完整链路为：

```text
任务定义
   ↓
调度 / 手动触发
   ↓
任务执行
   ↓
执行对象
   ↓
执行事件
   ↓
结构化日志
   ↓
中文 + 英文可读展示
```

v0.1.5 的任务中心开发应围绕这条链路推进，并持续复用 PackBreaker 已有的站点、下载器、验证、预演、执行计划、operation journal、回滚和源数据保护能力。

- 任务定义、任务来源、过滤、输出策略、执行策略、执行记录与事件的数据模型和 `0024_task_center_v015` 迁移；

- 新建手动任务“保存并开始”：保存后仅物化 `PENDING` 安全 Run，仍需经过 Preflight、人工审核与 execution gate 才允许副作用；
