# PackBreaker v0.1.9 发布说明与验收范围

## 本次变更

- 总览采用新的简约布局：顶部待审批、运行中任务、站点和下载器四张摘要卡；中部系统状态、磁盘、内存、CPU、下载器连接、站点连接六张独立状态卡；底部为统一任务生命周期。
- 增加本地资源只读指标。磁盘展示数据根所在文件系统；内存优先读取有效的容器 cgroup 限额，否则读取 Linux 系统内存；CPU 展示归一化的一分钟系统负载，**不等于实际 CPU 使用率**。
- 站点/下载器数量仅使用已有连接验证证据；总览刷新不会主动探测外部连接。未知、不可用、刷新失败时不伪报实时在线。
- 任务中心移除重复的新建入口及旧执行引擎兼容区独立展示；站点和下载器配置弹窗精简取消按钮；侧边栏在低视口仍可滚动，隐藏原生 Y 轴滚动条。
- 运行日志补充 HTTP 请求具体动作名称、常见系统组件日志的中文说明，原始诊断字段继续保留。

## 发布验证

以正式 GitHub Actions Release workflow 的成功结论为准，必须通过：

1. tag 与 `pyproject.toml` 版本一致，`release-baseline.json` 仍指向上一正式版 v0.1.8；
2. 仓库安全检查、Ruff、mypy、Vue typecheck、OpenAPI 漂移检查和前后端全量测试；
3. 浏览器端总览多分辨率、深色模式及低视口导航回归；
4. 从 v0.1.8 不可变镜像升级到候选版、恢复备份并回滚 v0.1.8，以及真实 Docker updater helper E2E；
5. 发布 `linux/amd64` GHCR 镜像、SPDX SBOM、release manifest、`SHA256SUMS` 与 GitHub Release，并在成功发布资产后推进 `stable` / `latest`。

## 安全与支持边界

本版不改变既有 PT/下载器支持矩阵、任务写入安全门、人工审批或文件系统 ownership 不变量。正式安装与回滚仍须使用发布清单中的**不可变镜像 digest**，不能把 `latest` / `stable` 当作不可变部署身份。

正式发布完成前，本文件仅表示发布候选范围，不构成已发布或真实 Docker 验收通过的声明。
