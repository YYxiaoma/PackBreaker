# PackBreaker v1.0.4 候选版：后续在线升级验收

## 候选范围

- 基线固定为 `release-baseline.json` 中已经发布的 v1.0.3 多架构不可变镜像；本候选不修改正式 v1.0.3 Tag、digest 或发布资产。
- 修复容器替换时未在 `HostConfig.Binds/Mounts` 声明、但在 `docker inspect .Mounts` 中实际存在的匿名 Docker Volume 身份丢失风险。仅以真实卷名称重挂载，保留只读状态；无法识别的挂载失败关闭，不执行切换。
- 原有配置 bind、媒体目录 bind、Docker socket 和 Compose 标签仍需保留；不修改真实 PT 站点、下载器或媒体。
- 候选版未发布，只有 GitHub Actions 的独立 Docker Runner 验收成功，才可以声称完成对应版本的真实升级路径。

## 兼容边界与验收门禁

**v1.0.3 → v1.0.4：** 因升级动作由已经发布的 v1.0.3 旧程序执行，旧程序无法读取 v1.0.4 的匿名卷修复代码。因此此条正式跨版本验收使用明确挂载的 `/data`，验证从正式基线本身发起的一次性 Updater、镜像与数据库身份、Docker socket、readiness、配置/数据保留及故障回滚。这不证明未声明的匿名 `/data` 可以直接由 v1.0.3 安全在线升级；有此部署形式的用户必须先在独立授权下安全固定原卷。

**v1.0.4 及后续 → 更新版本：** 在旧程序已包含此修复后，使用 Dockerfile 隐式生成的匿名 `/data` 与两个嵌套媒体目录 bind 做真实隔离升级，检查原卷名称、数据探针、媒体挂载源、Docker socket、健康状态及异常回滚。v1.0.4 的合成 ARM64 同版本替换可提前验证候选实现，但不能冒充未来的真实跨版本发布证据。

本候选推送仅启动测试分支的 CI / Candidate Docker E2E，不创建 Tag、GitHub Release 或更新 GHCR stable/latest，也不操作用户 NAS 生产容器。
