# 交互原型体验与需求覆盖

## 本轮交付

已实现可运行的 Vue 3 + Vite + Element Plus + TypeScript strict 前端原型，采用《PackBreaker-01-浅色控制台.png》的浅色侧栏、浅灰工作区、蓝色操作按钮与高密度任务列表。桌面任务表、移动任务卡片与深色主题共享同一交互模型。

本轮属于研发路线图允许提前进行的无外部副作用 UI 原型，不代表 M1–M6 已完成。不变更 v0.3 业务范围，因此不升级需求基线。

所有任务、文件路径、piece 结果、站点状态、日志和升级结果均为合成示例。原型不会读取媒体、创建硬链接、连接 PT 或下载器、发送通知、访问 Docker、操作生产数据库或实施真正的认证与加密。凭证控件禁用，不接收真实凭证。配置地址使用 `.invalid` 域名。

任务和配置保存在当前页面内存；刷新重置。仅深浅主题偏好写入 localStorage。导出文件包含演示 JSON，不是生产诊断包或数据库备份。规则配置控件展示并保存会话内设置，不构成后台调度器。

## 启动与体验

```powershell
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend dev
```

访问 `http://127.0.0.1:5173/`。默认仅监听本机回环地址。依赖已安装时，也可运行 `./scripts/start-prototype.ps1`。关闭终端或 Ctrl+C 停止服务；端口被占用时不会静默切换端口。

推荐体验顺序：

1. **任务中心**：10 个示例任务，按状态、站点、下载器或关键词筛选；选择活动任务后批量暂停；通过更多菜单恢复或取消，取消需确认影响范围。
2. **深空纪事**：打开审核，查看计划、候选证据、逐文件映射与时间线；批准后进入模拟客户端校验，点击「模拟校验完成」后进入做种。重复批准不会重复添加事件。
3. **远山回声**：执行按钮因歧义被禁用；选择文件映射中的正确源版本，应用后重新模拟验证，再审核新预演。
4. **候选变更**：选择 WEB-DL 示例候选后使旧预演失效，并要求客户端完整校验；长度不兼容的 Remux 候选保持阻断。
5. **森林之境**：位于列表第二页，也可直接搜索；查看缺失附件和跨文件 piece，体验人工、piece 修复计划；当前跨媒体示例不允许仅文件级修复。
6. **新建任务**：填写演示名称、处理类型、源/目标下载器与站点，生成预演。相同名称和目标的当前演示任务返回已有任务。正式系统将使用需求定义的源 hash、处理单元等幂等键。
7. **历史辅种**：新建扫描、推进合成进度、暂停、断点续扫；完成后生成代表性预演。此处不是实际目录扫描器。
8. **下载器**：配置映射，运行模拟诊断；切换跨文件系统异常查看阻断说明。
9. **清理与对账**：模拟对账，恢复结果待确认的登记动作；只能清理明确登记的 2 个链接，所有权未知资源始终不可删除。
10. **系统设置与升级**：体验通知开关、配置导出、恢复确认及升级成功/失败回滚路径。所有操作明确标注演示。

## 建议确认的问题

- 任务以大包为一级、单影片/单集为二级，是否符合日常管理习惯？是否需要任务列表直接展开所有单元？
- 候选证据、文件映射与预演的抽屉结构是否足够清晰？哪些字段需要固定在首屏？
- 需要按「源下载器」和「目标下载器」分别筛选吗？是否还需要错误码、验证等级与规则筛选？
- 一个处理单元同时选择多个站点候选的批量审核方式，应独立确认还是一次审核多个执行计划？
- 规则优先级、自动确认条件与通知事件是否需要进一步细化？
- 历史扫描结果是否需要先选择具体单元，再批量生成任务？当前按钮只生成代表性演示任务。
- 移动端任务卡片的密度、批量选择和详情入口是否符合使用习惯？

这些问题不擅自改变 v0.3 范围，待用户体验后决定是否更新需求与设计。

## 检查与工具

```powershell
pnpm --dir frontend lint
pnpm --dir frontend typecheck
pnpm --dir frontend test
pnpm --dir frontend build
# 先在另一个终端启动 dev，再检查浏览器
pnpm --dir frontend test:e2e
```

- Vitest：阻断安全门、qB/TR 跳过校验条件、重复批准、完整校验阶段、暂停恢复和组合筛选共 7 项。
- Playwright：任务审核、歧义映射修正、11 页导航、历史扫描、清理确认、移动视口和深色主题；浏览器 pageerror 必须为空。截图写入忽略的 `frontend/test-results/`。
- 类型检查使用 TypeScript strict；`lint` 当前是 Prettier 格式检查，未引入 ESLint。
- 本轮实际使用 Codex 提供的 Node.js 24.19.0、pnpm 10.34.5；尚未在 Node.js 22 或 Linux 环境运行验证。项目维持 Node.js 22.12+ 兼容配置，后续 CI 按基线补充 Node 22 验证。
- 未运行后端、安全文件系统、真实 PT/下载器、镜像构建与生产验收；这些能力尚未实现。
- Vue、Element Plus、Vite、TypeScript、Vitest、vue-tsc、Prettier 均用于对应界面与检查职责；Lucide 使用维护中的 `@lucide/vue`（ISC），替换弃用的 `lucide-vue-next`；Playwright 使用 Apache-2.0。其余许可证为 MIT 或 Apache-2.0，版本在 manifest 与 pnpm 锁文件中固定。

## 与正式实现的衔接

`src/demo.ts` 是专用合成演示模型；它不作为 API 类型、不执行真实安全判断。正式开发时由 OpenAPI 生成类型，通过 Pinia / Axios 和后端服务接入，移除前端模拟验证。需保留当前交互中的安全门、明确影响范围与人工确认过程，同时在后端重新实现并验证全部安全不变量。
