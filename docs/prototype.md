# 交互原型体验与需求覆盖

## 本轮交付

已实现可运行的 Vue 3 + Vite + Element Plus + TypeScript strict 前端原型，采用《PackBreaker-01-浅色控制台.png》的浅色侧栏、浅灰工作区、蓝色操作按钮与高密度任务列表。桌面任务表、移动任务卡片与深色主题共享同一交互模型。

界面最初作为研发路线图允许提前进行的无外部副作用 UI 原型；当前已开始按 M1 逐步替换为真实后端能力，但不代表 M1–M6 已完成。不变更 v0.3 业务范围，因此不升级需求基线。

任务、piece 结果、站点状态、日志、历史扫描、通知和升级结果仍为合成示例；不会连接 PT 站点、发送真实通知、执行 Docker 管理或进行辅种任务写操作。管理员认证、API Token 与“下载器”页面已经接入真实后端：首次访问可完成管理员初始化/登录/退出，安全设置可创建、一次性查看和撤销 API Token；下载器页可写入加密凭证、显式执行 qBittorrent/Transmission 只读连接探测，并在服务端执行路径映射与临时 hardlink 可行性诊断。界面不会读取或回显已保存凭证，也不会添加、删除、暂停、恢复或校验下载器任务。

演示任务、站点、规则和大部分设置仍保存在当前页面内存，刷新重置；管理员会话、API Token 元数据和下载器配置通过 FastAPI/SQLite 持久化。口令、API Token 明文和 CSRF 值不写入 localStorage；仅深浅主题偏好写入 localStorage。导出文件包含演示 JSON，不是生产诊断包或数据库备份。规则配置控件展示并保存会话内设置，不构成后台调度器。

## 启动与体验

```powershell
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend dev
```

访问 `http://127.0.0.1:5173/`。默认仅监听本机回环地址。Vite 开发服务把 `/api` 代理到 `http://127.0.0.1:8000`；需要同时启动 FastAPI。前端会根据 `/auth/me` 自动显示首次管理员初始化或登录界面，后端不可用时显示明确错误而不会进入伪登录状态。依赖已安装时，也可运行 `./scripts/start-prototype.ps1`。关闭终端或 Ctrl+C 停止服务；端口被占用时不会静默切换端口。

推荐体验顺序：

1. **任务中心**：10 个示例任务，按状态、站点、下载器或关键词筛选；选择活动任务后批量暂停；通过更多菜单恢复或取消，取消需确认影响范围。
2. **深空纪事**：打开审核，查看计划、候选证据、逐文件映射与时间线；批准后进入模拟客户端校验，点击「模拟校验完成」后进入做种。重复批准不会重复添加事件。
3. **远山回声**：执行按钮因歧义被禁用；选择文件映射中的正确源版本，应用后重新模拟验证，再审核新预演。
4. **候选变更**：选择 WEB-DL 示例候选后使旧预演失效，并要求客户端完整校验；长度不兼容的 Remux 候选保持阻断。
5. **森林之境**：位于列表第二页，也可直接搜索；查看缺失附件和跨文件 piece，体验人工、piece 修复计划；当前跨媒体示例不允许仅文件级修复。
6. **新建任务**：填写演示名称、处理类型、源/目标下载器与站点，生成预演。相同名称和目标的当前演示任务返回已有任务。正式系统将使用需求定义的源 hash、处理单元等幂等键。
7. **历史辅种**：新建扫描、推进合成进度、暂停、断点续扫；完成后生成代表性预演。此处不是实际目录扫描器。
8. **认证与下载器**：首次打开完成管理员初始化/登录；在“系统设置 → 安全与集成”创建或撤销 API Token，明文只展示一次；下载器页读取真实后端配置，新增/编辑只写凭证与路径映射，运行 qB/TR 只读连接测试，为每条映射提交真实测试文件执行路径/hardlink 诊断，并在所有安全门通过后启用。此页不提供任何下载器任务写操作。
9. **清理与对账**：模拟对账，恢复结果待确认的登记动作；只能清理明确登记的 2 个链接，所有权未知资源始终不可删除。
10. **系统设置与升级**：体验通知开关、配置导出、恢复确认及升级成功/失败回滚路径。所有操作明确标注演示。

## 建议确认的问题

- 任务以大包为一级、单影片/单集为二级，是否符合日常管理习惯？是否需要任务列表直接展开所有单元？
- 候选证据、文件映射与预演的抽屉结构是否足够清晰？哪些字段需要固定在首屏？
- 需要按「源下载器」和「目标下载器」分别筛选吗？是否还需要错误码、验证等级与规则筛选？
- 一个处理单元同时选择多个站点候选的批量审核方式，应独立确认还是一次审核多个执行计划？
- 规则优先级、自动确认条件与通知事件是否需要进一步细化？
- 历史扫描结果是否需要先选择具体单元，再批量生成任务？当前按钮只生成代表性演示任务。
- 移动端任务卡片的密度、批量选择和详情入口是否符合使用习惯？

这些问题不擅自改变 v0.3 范围，待用户体验后决定是否更新需求与设计。

## 检查与工具

```powershell
pnpm --dir frontend lint
pnpm --dir frontend typecheck
pnpm --dir frontend test
pnpm --dir frontend build
# 先在另一个终端启动 dev，再检查浏览器
pnpm --dir frontend test:e2e
```

- Vitest：原型安全门 7 项，加上 API problem 脱敏、强 ETag、下载器 `If-Match`、多 probe 诊断契约、管理员认证 store、API Token 明文不入 store 与服务端状态刷新，共 21 项。
- Playwright：默认拦截 `/api/v1/auth/me` 为合成的已认证管理员状态，因此不依赖真实后端或真实口令；继续覆盖任务审核、歧义映射修正、11 页导航、历史扫描、清理确认、移动视口和深色主题，浏览器 pageerror 必须为空。截图写入忽略的 `frontend/test-results/`。
- 本轮 Linux Runner 未安装脚本默认使用的 Microsoft Edge，也没有可复用的系统 Chromium；`test:e2e` 在浏览器启动阶段终止，因此本轮不把 Playwright 记为通过。Vite 8.2.2 开发服务已确认可在 5173 正常启动。
- 类型检查使用 TypeScript strict；`lint` 当前是 Prettier 格式检查，未引入 ESLint。
- 当前前端验证使用 Node.js 22.23.2、pnpm 10.34.5，在 Linux Runner 上执行；后续 CI 仍需把该矩阵固化为发布门禁。
- 默认前端/后端自动测试不访问真实 PT 或下载器。真实下载器只读连接探测与路径诊断必须由用户在已配置环境中显式触发；镜像构建与生产验收仍待完成。
- Vue、Element Plus、Vite、TypeScript、Vitest、vue-tsc、Prettier 均用于对应界面与检查职责；Lucide 使用维护中的 `@lucide/vue`（ISC），替换弃用的 `lucide-vue-next`；Playwright 使用 Apache-2.0。其余许可证为 MIT 或 Apache-2.0，版本在 manifest 与 pnpm 锁文件中固定。

## 与正式实现的衔接

`src/demo.ts` 仍是任务等页面的专用合成演示模型，不作为 API 类型、不执行真实安全判断。认证、API Token 和下载器切片已经通过 Pinia / Axios 与后端服务接入，并把 HTTP/CSRF/problem+json/ETag 处理集中在 `src/api/`。仓库跟踪 `frontend/openapi.json` 与 `src/api/generated/schema.ts`，认证/API Token 已直接使用生成类型；下载器响应待服务端补齐显式 response model 后再移除手写 view 类型。其他页面迁移时继续保留当前交互中的安全门、明确影响范围与人工确认过程，同时以后端安全判断为唯一执行依据。
