# PackBreaker v1.0.12 研发说明

## 1. 版本目标

v1.0.12 聚焦任务中心交互统一、手动拆包来源快照可靠性、执行详情中文化与任务日志可读性，不扩展新的拆包业务能力。

本版本范围：

1. 任务中心三张任务卡增加明确选中态，默认选中“手动拆包”；前两张卡片名称统一为“手动拆包”“监控拆包”。
2. 顶部“新增任务”不再依赖当前卡片，统一先选择“手动拆包 / 监控拆包 / 影片去重”，再进入对应表单。
3. 修复手动拆包表单“扫描预览”按钮默认状态文字与背景对比度不足。
4. 任务详情、执行记录详情、目录扫描预览、影片去重候选等信息展示由 Drawer 改为 Dialog；目录/种子选择器仍保留选择型 Drawer。
5. 修复手动目录任务保存后立即执行时误报 `SOURCE_SNAPSHOT_CHANGED`。
6. 生命周期、风险/授权、校验/收尾、结果/错误等执行详情以中文为主展示，保留技术码辅助排障。
7. 任务列表保持单行，超长内容省略并提供 Tooltip；操作列固定“查看 / 执行 / 删除 / 更多”。
8. 任务执行日志增加中文事件摘要、结构化上下文与快照变化字段，提升日志页可读性。

## 2. SOURCE_SNAPSHOT_CHANGED 根因与修复

### 2.1 现场现象

用户提供的 2026-10-05 日志中，一次手动拆包执行共生成 43 个对象，其中 41 个在 materialize 阶段以 `SOURCE_SNAPSHOT_CHANGED` 被拒绝。目录预览、保存任务和自动执行仅相隔约十几秒，用户确认期间没有修改媒体文件。

### 2.2 根因

目录预览快照原先包含：

- `size_bytes`
- `device`
- `inode`
- `mtime_ns`

后端把 `mtime_ns` 作为 JSON integer 返回，前端 TypeScript 又将其声明为 JavaScript `number`。现代文件的纳秒时间戳约为 `1.7e18`，已经远超 JavaScript `Number.MAX_SAFE_INTEGER`（`2^53 - 1`）。因此：

1. 后端产生精确的 64 位纳秒时间戳；
2. 浏览器解析 JSON 后发生 IEEE-754 舍入；
3. 前端把已舍入数值保存回 `selected_files`；
4. 执行时后端重新扫描获得精确 `mtime_ns`；
5. 精确比较失败，错误判断为文件已变化。

### 2.3 v1.0.12 协议

- 新目录预览 API 把 `mtime_ns` 作为十进制字符串传输。
- 前端 `TaskDirectoryFile.mtime_ns` 改为 `string`，禁止再次经过 JS Number。
- 新任务保存后按纳秒级精确值比较。
- 为兼容 v1.0.11 及更早版本已保存的任务，如果数据库中的旧快照仍是 integer，只接受“当前真实 `mtime_ns` 经 JavaScript Number 确定性舍入后恰好等于旧值”的情况；不使用宽泛时间容差。
- 当快照确实不一致时，`technical_detail` 明确记录 `size_bytes / device / inode / mtime_ns` 中实际变化的字段。

该方案既消除前端整数精度误报，也继续保证真实文件变化必须被安全阻断。

## 3. 任务中心交互

### 3.1 卡片

- 默认：手动拆包。
- 选中态：边框、浅色背景、图标反色和轻微阴影共同表达。
- 三卡片名称：
  - 手动拆包
  - 监控拆包
  - 影片去重

### 3.2 新增任务

顶部“新增任务”统一打开任务类型选择 Dialog。选择后：

- 手动拆包：进入现有手动任务表单。
- 监控拆包：进入现有监控任务表单。
- 影片去重：进入现有影片去重表单。

底层 API 仍保持各领域现有接口，不为了 UI 统一而强行合并后端模型。

### 3.3 列表与操作

手动/监控任务列表：

- 主字段单行显示；
- 超长内容省略；
- Element Plus Tooltip 显示完整内容；
- 操作列固定：查看、执行、删除、更多；
- 暂停/恢复、失败重试、编辑、克隆进入“更多”。

影片去重列表同样统一为：查看、执行、删除、更多。

影片去重新增安全删除 API。删除只移除 PackBreaker 数据库中的任务、候选和 journal 记录，不触碰 A/B 目录媒体文件；运行中、待审核、待恢复任务禁止删除，避免丢失恢复和审计证据。

## 4. 详情中文化

主要 UI 使用中文：

- 生命周期：发现对象、分析与预检、候选审核、生成执行计划、风险授权、执行副作用、结果校验、收尾与对账、已完成。
- 风险：待评估、低风险、高风险。
- 授权：尚未进入授权阶段、等待候选确认、已自动授权、等待高风险授权、已授权、已拒绝、已阻断、授权流程完成。
- 执行阶段：等待执行、发现源数据、分析文件、扫描站点、准备执行、正在拆包、写入输出、验证结果、已完成、失败、已跳过。
- 收尾：等待收尾、收尾完成、需要人工关注、正常、未知、不适用。
- 结果：成功、失败、已跳过、已取消。

英文枚举、错误码、Plan ID、Trace ID 等仍作为技术信息保留。

## 5. 日志改造

任务事件 message 改为中文主描述，并保留稳定的 `event_code`。

重点事件上下文增加或明确展示：

- 对象总数 / 可执行 / 失败 / 跳过；
- 来源类型；
- 来源对象路径；
- 快照变化技术详情；
- 生命周期阻断原因；
- 风险等级；
- Execution Plan / Approval / Run ID；
- 阶段与结果迁移；
- 扫描发现数、新对象数。

日志页显示结构：

1. 中文事件标题；
2. 中文事件说明；
3. 本次事件的具体 message；
4. 技术事件码；
5. 任务名、执行记录、Trace；
6. 中文字段名的结构化上下文。

## 6. 已完成回归验证

- 手动目录快照精度回归测试：使用无法被 JavaScript Number 精确表示的真实纳秒时间戳，目录预览以字符串返回，保存后立即执行不再误报。
- 现场规模回归：创建 43 个真实临时媒体文件，完整执行“目录扫描预览 → JSON 往返 → 保存任务 → 立即执行”，43 个对象全部进入安全执行链，失败数与跳过数均为 0，未产生任何 `SOURCE_SNAPSHOT_CHANGED` 拒绝事件。
- v1.0.11 旧 JS Number 快照兼容测试：确定性舍入值可继续执行。
- 文件真实修改后仍会触发 `SOURCE_SNAPSHOT_CHANGED`。
- 影片去重服务测试包含安全删除和运行中删除阻断。
- 浏览器 E2E 已覆盖三任务卡片默认/切换选中态、跨卡片统一新增任务、扫描预览按钮默认对比度、列表固定操作列、主字段单行显示，以及任务详情/执行详情 Dialog 化。
- 前端 Vue TypeScript 校验通过。

正式发布前仍需运行完整 `scripts/check.py`、`scripts/test.py`、前端 test/build，以及候选镜像 E2E。

## 7. 候选镜像交付

新增手动工作流 `.github/workflows/candidate-v1012-image-delivery.yml`。候选交付保持与上一版本一致的不可变策略：

- 仅允许手动 `workflow_dispatch`；
- 输入必须是已审查的 40 位 candidate commit SHA；
- 候选版本固定校验为 `1.0.12`；
- 同一 multi-arch 构建同时推送 GHCR 与 Docker Hub；
- 候选 tag 为 `candidate-v1.0.12-<commit前12位>`；
- 两个 registry 必须解析到同一个 immutable digest；
- AMD64 与原生 ARM64 都验证运行时版本与 commit identity；
- 候选工作流不创建正式 Git Tag / GitHub Release，也不推进 `latest` / `stable`。
