# PackBreaker v1.0.13 研发说明

## 版本目标

v1.0.13 聚焦总览与运行状态一致性、在线升级兼容性和 Synology 资源指标可观测性，不新增数据库迁移。

本版本解决以下问题：

1. 在线升级因旧 `/data` 数据根不存在而被 `DATA_ROOT_UNAVAILABLE` 错误阻断。
2. 删除右上角用户框左侧重复的“系统需要关注”状态提示。
3. 修复总览“系统状态”与其四个可见子服务状态不一致。
4. 修复总览“运行中任务”使用旧底层 `UnpackTask` 口径导致重复计数。
5. 删除站点卡片中的“已完成适配”文本。
6. CPU 负载历史从页面生命周期迁移到后端应用生命周期持续采样。
7. 修复 Synology cgroup v1 / hybrid 环境下内存指标为空。

## 1. 在线升级与显式媒体挂载

### 问题

历史发布预检强制检查 `PACKBREAKER_DATA_DIR`（默认 `/data`）必须存在、可读、可遍历。当前 PackBreaker 已支持任意显式 Docker 媒体挂载，例如 `/downloads`、`/downloads2`，因此旧数据根不存在不应阻断容器在线升级。

### 调整

`release_preflight._check_data_root()` 保留兼容检查，但将旧数据根不可用从 blocked 降为 warning：

- code: `LEGACY_DATA_ROOT_OPTIONAL`
- 不加入升级 blocked codes
- 配置目录、数据库、secret、备份和 updater 安全门仍维持 fail-closed

媒体目录安全边界继续由显式 mount discovery、AuthorizedPathScope 和 updater 容器挂载保留逻辑负责。

## 2. 顶栏系统状态提示

删除 App 顶栏独立的 system-health 请求、60 秒轮询和状态按钮。总览页继续作为系统状态的唯一主要展示入口，避免重复请求和两个状态入口口径不一致。

通知红点、用户菜单和版本升级入口保持不变。

## 3. 总览系统状态口径

后端完整 `SystemHealthReport.status` 仍聚合全部运维检查，用于诊断和导出。

总览“系统状态”卡只根据页面实际展示的服务计算：

- Web 服务：健康接口成功即视为可用
- 调度服务：`workers`
- 存储服务：`storage`
- 数据库：`runtime`

优先级为 blocked > warning > ok。备份、通知、站点、下载器、任务积压等不可见检查不再导致该卡片与四个子状态矛盾。

## 4. 运行中任务统计

旧实现直接统计 `UnpackTask` 的多个运行阶段，一次统一任务执行可能产生多个底层子任务，因此总览数量可能大于任务中心可见执行数。

v1.0.13 的总览 `tasks.running` 改为：

- `TaskExecution.status == RUNNING`
- 加上 `MovieDedupJob.status == RUNNING`

同时保留旧 `UnpackTask` 的 RETRY、stale、active 等运维积压指标，用于健康诊断，但不再作为用户可见“运行中任务”KPI。

## 5. 站点卡片

站点列表卡片不再展示 support status 中的“已完成适配”。

站点 profile 的 `support_status`、未开放适配器限制、真实验收限制、新增/编辑表单标签与启用安全门保持原有逻辑，不因隐藏卡片文案而削弱能力判断。

## 6. CPU 负载持续采样

新增应用级 `SystemResourceSampler`：

- 应用启动即开始采样，不依赖进入总览页面
- 默认每 30 秒采样
- 内存 ring buffer 保存最近 12 个样本
- 不写 SQLite，避免 NAS 持续写放大
- 页面切换不会清空历史
- 容器重启后重新积累

`/system/health` 的 resources metrics 提供当前值与最近历史样本；前端总览只读取后端历史，不再自行维护 CPU 数组。

CPU 指标仍定义为“1 分钟系统 load / 逻辑 CPU 数”的归一化百分比，不声称为瞬时 CPU utilization。

## 7. Synology 内存指标

`_memory_metrics()` 调整为三级只读回退：

1. cgroup v2: `memory.max` / `memory.current`
2. cgroup v1: `memory.limit_in_bytes` / `memory.usage_in_bytes`
3. `/proc/meminfo`: `MemTotal` / `MemAvailable`

cgroup 文件缺失或不可读时不再丢弃已经成功读取的 `/proc/meminfo` 数据。

有有效容器内存限额时优先展示容器限额；否则显示容器可见的系统内存。

## 兼容性与迁移

- 数据库迁移：无
- 任务定义模型：无破坏性变化
- 旧 `/data` 部署：继续兼容
- 任意显式媒体挂载：在线升级不再因缺失 `/data` 被误阻断
- system health API：保持现有结构，仅新增 resources/tasks 聚合 metric keys
- 正式发布基线：保持 v1.0.12
