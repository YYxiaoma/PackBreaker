# PackBreaker v1.0.11 热修复研发说明

## 1. 背景

v1.0.10 正式发布后，在部分 NAS 内网 HTTP 访问场景中，用户从 v1.0.9 点击“立即升级到 v1.0.10”时，前端在真正调用 updater API 之前抛出：

```text
TypeError: crypto.randomUUID is not a function
```

典型访问地址为 `http://<NAS-LAN-IP>:<PORT>`。部分浏览器只在安全上下文中暴露 `Crypto.randomUUID()`，因此直接调用会阻断升级请求。

控制台中的 CookieCloud content script 日志属于浏览器扩展注入，与 PackBreaker 在线升级故障无关。

## 2. 根因

v1.0.10 前端多个需要幂等键/nonce 的操作直接调用 `crypto.randomUUID()`：

- 在线升级
- 影片去重执行
- 任务失败重试
- 任务生命周期推进
- 高风险审批
- 安全修复

这些功能在 HTTPS、localhost 等安全上下文中工作正常，但在部分普通 HTTP LAN 地址下 `crypto.randomUUID` 不存在。

## 3. 修复设计

新增统一客户端 nonce 生成器 `frontend/src/clientNonce.ts`：

1. 优先使用浏览器原生 `crypto.randomUUID()`；
2. 若 `randomUUID` 不可用，但 `crypto.getRandomValues()` 可用，则生成 RFC 4122 v4 UUID；
3. 若 Web Crypto 完全不可用，退化为时间戳 + 两段随机串；
4. nonce 仅用于请求幂等标识，不作为密码、token 或加密密钥。

所有前端直接 `randomUUID()` 调用统一迁移到该 helper，避免同类功能在 HTTP 内网访问下继续失败。

## 4. 在线升级专项回归

Browser E2E 在页面初始化前主动移除 `Crypto.prototype.randomUUID`，并硬断言：

```text
typeof crypto.randomUUID === "undefined"
```

随后继续执行完整版本弹窗“一键升级”流程，必须满足：

- 不弹额外确认框；
- 成功生成 `pb-upgrade-*` 幂等键；
- 成功调用 `/api/v1/system/upgrade/actions`；
- updater 状态进入 accepted；
- 进度条与处理内容正常显示；
- 不因 nonce fallback 产生重复升级请求。

## 5. 影响范围

本次为纯前端兼容性热修复，不修改：

- updater 后端协议；
- Docker helper 执行逻辑；
- 数据库/Alembic；
- GHCR/Docker Hub 镜像协议；
- 生产 Synology 配置。

项目版本推进为 `1.0.11`。

## 6. 验收门禁

发布 v1.0.11 前至少要求：

- nonce 单测覆盖原生 `randomUUID`、`getRandomValues` fallback、无 Web Crypto fallback；
- Vue TypeScript 检查通过；
- Browser E2E 在明确禁用 `randomUUID` 后通过；
- `scripts/check.py` 全绿；
- `scripts/test.py` 全绿；
- 正式候选镜像通过 AMD64/ARM64 与 GHCR/Docker Hub 同 digest 验证；
- 正式发布前以上一正式版 v1.0.10 作为相邻升级/回滚 baseline。
