# v1.1.2 CarPT 受限真实验收模式（第一阶段：只读执行）

> 本功能是**按单个手动任务授予短期站点只读验收权限**，不是把 CarPT 从 `PENDING_REAL_VALIDATION` 改为正式 `SUPPORTED`。第一阶段仅允许任务启动、站点匹配、torrent 获取与媒体内容只读验证，**绝不允许文件物化、辅助文件下载或外部下载器 ADD/RECHECK/START 写入**。七站真实完整 E2E 依然未通过，正式发布继续阻断。

## 现有隔离任务

- 原实例：`runtime/v111-cookiecloud-review`（带既有 CookieCloud、CarPT Cookie、Transmission 与 qB）
- 已存任务：`f432f681-8d36-4927-b79e-b0e10fbaa535`，手动、指定 1 部影片、来源为《九品芝麻官》原目录、扫描站点仅 CarPT、目标下载器仅 Transmission
- 输出：`/workspace/PackBreaker/runtime/data/downloads2/packbreaker-v112-isolated-acceptance`
- 存储方式：`COPY`（独立 inode）；冲突策略：`VERIFY_REUSE_OR_STOP`；自动重试：关闭
- 站点 CarPT 仍未启用为全局站点，`SiteService.enabled_adapters()` 对普通任务不可见。已有其他站点和其他任务不会由此获得权限。

## 权限文件及只读冻结

仅在管理员明确授权后，由受控本地操作在实例 config 目录写入：

`v112-unpack-readonly-acceptance.json`

文件必须是 `0600` 的非符号链接普通文件（不超过 4 KiB），包含 **恰好**九个字段：

```json
{
  "schema": "packbreaker-v112-readonly-site-acceptance-v1",
  "definition_id": "f432f681-8d36-4927-b79e-b0e10fbaa535",
  "site_id": "<existing CarPT site UUID>",
  "site_version": 1,
  "downloader_id": "<existing Transmission downloader UUID>",
  "source_directory": "<approved exact original source directory>",
  "source_filename": "<exact selected .mkv basename>",
  "output_directory": "/workspace/PackBreaker/runtime/data/downloads2/packbreaker-v112-isolated-acceptance",
  "expires_at_utc": "<short UTC ISO-8601 expiry, within 72 hours>"
}
```

站点必须是具有原有有效凭据、连接 `OK` 且未在正式 Registry 开放的 `CARPT`；目标下载器必须是已启用且连接 `OK` 的 `TRANSMISSION`。校验任务 ID、站点 ID/版本、下载器 ID、来源目录、**单个**选中视频及严格输出路径；源/目标/执行模式或版本有任意变化、文件过期/缺失/权限不符都拒绝匹配。不能借用其他站点、任务、影片或下载器。

验收任务启动后在 `execution.config_snapshot.acceptance_mode` 写入 `READ_ONLY_SITE_ACCEPTANCE` 冻结标记，随后即使撤销权限文件、修改任务或禁用站点，物化、辅助文件 staging、外部种子 ADD/RECHECK/START 均继续禁止。读阶段只会为该精确 execution 提供 CarPT 适配器，**不更改生产全局 Enabled Adapters 或 Registry 状态**。

## 冻结执行计划的可重复只读预检（v1.1.2）

已经完成原 execution 的 `FULL_VERIFIED` 与冻结计划后，可以从仓库根目录运行（参数为占位；不要把真实数据库、源媒体或私有路径提交到仓库）：

```bash
.venv/bin/python -m scripts.v112_readonly_acceptance_preflight \
  --db "/ABSOLUTE/INSTANCE/packbreaker.db" \
  --execution-id "<existing frozen read-only execution UUID>" \
  --approved-parent "/ABSOLUTE/EXPLICITLY_APPROVED/MOUNT/ROOT" \
  --expected-output "/ABSOLUTE/EXPLICITLY_APPROVED/MOUNT/ROOT/isolated-output"
```

- 只通过只读 SQLite 查询和 `lstat`、文件快照元数据、`disk_usage` 检查冻结计划与环境；不会读取媒体内容、操作 PT/下载器或创建目录。父目录和精确目标由调用方输入；工具检查目录结构，**不能独立证明路径已获得真实副作用授权**。
- JSON 输出只含安全错误码、布尔项、文件数量及估算大小，不含源媒体路径、torrent、Cookie、Passkey、下载器连接参数或原始操作意图。数据库、计划摘要、候选绑定或冻结只读标记不匹配时退出码为 **2**。
- `BLOCKED_OUTPUT_ROOT_MISSING` 仅表示冻结只读任务其它本次可核查前提满足，且唯一冻结阻断为目标根缺失；其余情况为 `BLOCKED_OTHER_PRECONDITION`。两者**都不是验收通过或写入授权**；返回 `writes_authorized=false`。
- 即使后续准备好目标根，原 execution 仍保持只读冻结，不能被原地解冻。空间及源文件快照只是检查时的临时证据，不能替代写入前的身份、归属与原子预检。
- 真实写入必须另行实现并获相应范围授权，使用新的受控 execution 和先 journal 后副作用的幂等链；此工具的结果不能代替七站 E2E 中的媒体物化、客户端下载校验/启动或 journal 恢复收据。

## 第二阶段开发安全边界：验收标记不等于写入授权

- 正式新增站点的真实写入验收需要**全新 execution**；原 `READ_ONLY_SITE_ACCEPTANCE` execution 的冻结标记永远保留，不得复用或原地转成可写。输出根必须先在获批准的隔离执行环境中由独立受控操作准备，后续新计划重新检查 source snapshot、target root、目标下载器 save path、binding digest 和冲突情况。现有只读预检不能替代这些检查。
- 未来可能使用的 `SCOPED_WRITE_SITE_ACCEPTANCE` **仅是预留的语义名称，不是可用功能或有效授权标记**。现阶段 worker 对 `execution.config_snapshot` 中存在任何 `acceptance_mode` 键的执行全部阻止，包括原只读值、未知值、空字符串及 JSON null；普通不带此键的正式站点 execution 不受影响。调度 SQL 也只接受 JSON object 且缺少该键，防止直接调用执行服务或自动任务扫描时出现语义不一致。
- 下一开发阶段须先实现独立的**正向授权机制**：严格指定一个新 execution、一个候选及完整 plan digest、CarPT 和 Transmission 的固定配置/版本、单媒体源身份、COPY、精确隔离目标，使用限时不可泛化凭据与执行环境的独立写入批准；每次提交真实文件系统/客户端下载器操作前仍须确认许可未撤销和 journal 归属，再按既有先记录 intent、后执行、失败人工对账规则推进。
- 即使未来代码具备正向授权，执行环境安全拦截依旧有效；不能擅自修改受控路径外的权限或利用其它执行工具绕过拦截。不允许无 journal 认领既有种子、原媒体覆盖、自动清理或解除七站发布门禁。

## 第二阶段增量：独立新 execution 的许可提案只读核验器

- 新增 `backend/app/application/unpack_scoped_write_proposal.py`，定义独立于原 `v112-unpack-readonly-acceptance.json` 的 `v112-unpack-scoped-write-proposal.json`。这是**仅供将来审批前核对的提案数据文件**，不是有效令牌、UI 授权或可以执行写入的许可。没有 API 自动创建该文件，也没有任何 worker 消费该核验器的返回值。
- 提案必须是最大 4096 字节、权限不宽于 `0600`、非 symlink 普通文件，具备**恰好 21 项固定字段**。核对新 execution ID/definition 版本、一个 item/candidate/generation、冻结 plan digest、已独立 `FULL_VERIFIED` 的 torrent 摘要、CarPT 配置 ID/版本、Transmission ID/版本及 binding digest、单个原媒体、COPY 目标、客户端远端保存目录与目标设备号；有效期严格不超过 **1 小时**，过期、撤销、身份变化或计划变更即不匹配。
- 检查只读取配置文件和数据库中的冻结元数据：计划必须真实 `ready`、候选/物化计划 digest 完整、当前项目仍为 CarPT `PENDING_REAL_VALIDATION` 和禁用状态、Transmission 为可用配置、初始操作 journal 为零。任何文件名路径穿越、不安全绝对路径、不一致候选、非预期模式、源目标重叠都失败关闭。
- **安全边界不可混淆**：`matches_frozen_preflight(...) == true` 只表示提案元数据相符，**不是用户/执行环境批准，更不是写操作准入**。所有带 `acceptance_mode` 的 worker 仍 100% 拒绝执行；该核验器不访问 PT、客户端下载器、NAS、媒体，也不负责探测目标文件系统现态。后续必须另加执行环境独立批准、实时快照/无冲突判断、先 journal 后副作用的逐操作准入、撤销与并发恢复，才能考虑独立真实写验收。

## 受控写入操作 journal 风险分级（仅离线决策，不授予写入）

- 新增 `backend/app/domain/unpack_acceptance_operation_review.py`，供离线合成与审计工具研究后续安全阶段。支持且**仅模拟**目录创建、COPY、Transmission ADD / VERIFY / START 五类操作；明确拒绝 HARDLINK、SYMLINK、REMOVE 及未列明的操作。
- 请求与提案冻结 execution/item/plan digest、影片项版本必须一致；文件目标须为精确隔离根内规范绝对路径，Transmission 目标须严格对应已冻结的远端 save path。journal 的 item、plan digest、idempotency key、类型及目标必须完整对齐；相同 key 或不同 key 对同一 `APPLIED` 目标的重复证据都拒绝。
- 对没有 intent、未知外部结果的 `INTENT_RECORDED`、已 `APPLIED`、人工对账中、终止状态作不同风险分级。ADD 前必须具备全部 COPY `APPLIED` 证据，VERIFY 先有 ADD `APPLIED`，START 先有 VERIFY `APPLIED`；缺少前序记录、许可文件已撤销、影片项版本变化、操作身份漂移，一律不能按正常可执行处理。
- **所有结果的 `writes_authorized=false`、`realtime_proof_verified=false`、`external_client_contacted=false` 为不可变值。** 即使返回 `INTENT_NOT_RECORDED` 也仅表示离线风险分类，绝不允许跳过真实执行前的用户/主机授权、现态预检及先 journal 后副作用的原子提交；未知结果必须独立对账。该模块没有接入写 Worker、API 或生产调度。

## 第二阶段：事务级验收冻结检查（生产 Worker 仍不可写）

- 无论自动调度曾通过何种旧检查，三个 Worker 在每笔外部操作意图记录时均从**同一个 BEGIN IMMEDIATE SQLite 事务**重新查出 execution 并检查 `acceptance_mode`：不存在/损坏的执行快照或存在该键（含旧只读和未来预留可写模式）即稳定拒绝，不能创建 journal，更不能到达媒体 COPY/Transmission ADD、VERIFY、START。
- 文件落位计划预留、辅助补齐上下文读取和最终辅种准备也执行前置拦截。若授权标记在调度和事务之间改变，Worker 忽略 stale batch，不可把受保护任务误改成失败或重置 item 版本；GET-only 下载器诊断继续保持原样。
- 该变更只加强现有默认拒绝的事务屏障，不授予任何新的正向写入能力。未来正向授权必须替换为严格 execution/plan/path/device 绑定及有效期/执行环境批准，而不是从 batch 层绕过本门禁。

## 新 CarPT 受控写入提案：隔离目录及源文件现态只读检查

- `inspect_scoped_write_environment()` 不使用站点/下载器 RPC，不读媒体内容，也不创建目录：接收已冻结的 `UnpackExecutionPlan`、未来提案绑定的源目录/影片名以及**独立可信的**隔离父目录和单一输出根；输出根必须已存在、为空、非符号链接、计划目标设备号一致，所有源文件必须是同一源目录下的普通文件且快照未变化。
- 对全部 COPY 字节做卷剩余空间核对；对未知既有输出、额外越界源、复用、硬链接/符号链接写模式、源输出交叠、失效快照、错误目录/设备号与符号链接祖先失败关闭。扫描结束前再次核对目录身份、空目录与源文件快照，以检测部分扫描中途漂移；任何并发变化后仍可能发生，需要未来独立的 descriptor-bound / atomic 写意图门禁。
- 正常结果固定为 `METADATA_ONLY_NO_GRANT`，并持续返回 `writes_authorized=false` 和 `descriptor_bound_write_permission=false`。当前没有面向真实 execution 的生产调用路径，不能因为元数据检查成功就操作目录、原真实媒体、Transmission 或文件 journal。

## 新阶段：只读目录描述符绑定复核

- `inspect_scoped_descriptor_evidence()` 在上一阶段的路径型元数据检查之外，从 `/` 开始逐级采用 `O_NOFOLLOW|O_DIRECTORY` 的 `openat(dir_fd)` 锁定检查期的目录对象，再以 `O_PATH|O_NOFOLLOW` 打开源文件**仅元数据**句柄，不读取源内容；目标目录通过已打开 FD 读取空目录状态和剩余空间，并在结束前重复打开路径、核对 inode/device/源文件快照。测试对扫描期间目录改名/替换、源文件替换、改为 symlink、目标意外出现文件等必须返回阻断。
- 这只是**可审计的只读观察**，不是锁住目录供后续写入，更不是宿主机管理员授权；返回 `OBSERVED_ONLY_NO_GRANT` 时 `writes_authorized=false`、`descriptor_bound_write_permission=false`。旧 READ_ONLY execution、三个写 Worker 和七站发布门禁保持原样。未来必须在真实副作用执行期间持续使用经独立批准的 FD 与原子 journal 写前检查，才能从观察走向受控真实 E2E。

## 新阶段：生产 SQLite journal 格式只读对账

- `audit_scoped_carpt_journal_rows()` 从实际 ORM 数据模型读取单个**新** scoped execution 的 frozen item/plan 和 journal，检查 COPY、目录创建、Transmission ADD、VERIFY、START 对应的真实 `target/intent` 字段，而不是泛化的路径假值。必须一致的身份包括 item、计划摘要、候选代次、来源路径/目标路径、下载器、torrent hash、远端保存路径和由 `item_id:plan_digest` 确定性生成的 ownership tag。
- 返回状态区分 `NO_INTENT_NO_GRANT`、`RESULT_UNKNOWN`、`RECONCILE_REQUIRED`、`BLOCKED_SEQUENCE`、`BLOCKED_JOURNAL` 和 `APPLIED_EVIDENCE_ONLY`，其中**没有一个代表可执行或可重放授权**。任何未知结果/归属冲突必须独立人工对账，不能因为数据库记录为 APPLIED 就推测客户端仍在播种或文件未变化。
- 该模块既不创建 journal，也不更新审核实例数据库；唯一作用是供后续独立授权与实时客户端/文件系统收据链调用前进行只读审计。旧冻结 execution、实际下载器和全部站点 Registry 保持不变。

## 只读初始准入整合入口：三个检查器关联同一冻结身份

- `inspect_pristine_scoped_carpt_chain()` 接收当前 ORM session、受控提案 inspector、全新 execution/item、来自独立可信来源的批准父目录/精确输出根以及当前时刻；验证相同的冻结计划、源文件、隔离目录、可用空间和零 journal 身份，扫描结束时二次读取提案与 ORM 当前状态，拒绝扫描期间撤销、版本变化或新插入 intent。
- 它只报告 `OBSERVED_ONLY_NO_GRANT` 或阻断状态，**任何结果都不能转化为写入**。不会启用旧冻结执行、不会创建目录和 journal、不会访问真实客户端，也不会恢复已有 ADD 或复制操作；合成测试保留完整撤销/并发失败关闭用例。

## 只读证据链的异常输入失败关闭加固

- 提案 inspector 对执行配置快照非 JSON object（`null`、字符串、数组、数字）必须返回 `False`，不得因 `.get()` 异常中断审计并混淆准入结果。
- SQLite journal 的路径审核显式拒绝实际 `NUL` 字符及**单个**反斜杠，同时保留 `.`、`..` 和多余分隔符的失败关闭；用已失败的负例回归确认修复，不把模拟通过当成真实主机写入授权。

## 提案轮换检测：绑定同一 inode 的只读证据

- 现有只读检查链除比较提案 JSON 外，还核对提案文件的 `device/inode/size/mtime_ns/ctime_ns`，从 `O_NOFOLLOW` 打开的 FD 读取，开始和结束均再次核对文件名指向同一对象。即使中途换成**完全相同 JSON 内容**的新文件，也须返回 `BLOCKED_PROPOSAL`；仅改变时间戳同样失败关闭。
- 此处的 FD 身份是一次只读观察，不可复用为文件/下载器写入授权。独立宿主机许可与原子执行事务仍未完成，禁止启用真实 COPY/ADD/VERIFY/START。

## 首笔外部操作的事务级模拟（并非写入授权）

- `inspect_initial_scoped_intent_transaction()` 在真实 SQLite `BEGIN IMMEDIATE` 中调用受控提案/冻结计划/源文件 FD/零 journal 证据链，并以当前计划严格核对唯一首笔目录创建（没有目录时才考虑首笔 COPY）及全局幂等键无冲突。整个过程**不记录任何外部 intent**，并在释放 SQLite 锁时 rollback。
- 即使返回 `FIRST_INTENT_SHAPE_ONLY_NO_GRANT` 也始终 `writes_authorized=false`，不具备宿主机授权、外部写操作回执、重放许可。它与实际生产写入 Worker 完全隔离，无法借此对原冻结 execution 进行任何目录、媒体或客户端操作。未来仍需实时 FD + 独立 host approval + 先 journal 后副作用的正向执行链。

## 合成 journal 的原子提交与回滚演练（严格不进入生产）

- 从现有第一笔 SQLite 事务预检抽出仅供内部测试组合的持锁只读核验函数，原有独立入口依然只返回 `NO_GRANT` 并 rollback。测试文件在 `tmp_path` 下显式模拟不存在的主机授权，并在同一个 `BEGIN IMMEDIATE` 中向**临时 SQLite** 追加合成 `INTENT_RECORDED` 行；证明提交后重复请求阻断、提交前崩溃回滚、另一连接写锁被排斥、撤销/旧只读/路径错误不能产生 journal。
- 该测试代码不属于生产授权接口；现有三个 Worker 对所有验收标记继续拒绝，真实宿主机目录、CarPT、Transmission/NAS、Docker 镜像没有任何副作用。绝不能用测试通过替代正向 host approval、真实媒体 COPY/Downloader ADD/VERIFY/START 和 7/7 真实站点验收。

## 分离的 host approval 证据文件：独立观察但不代表许可

- 提供选填 `HostApprovalEvidenceInspector`，只检查独立受控文件（不能直接信任 proposal 自报字段）的文件所有权/0600/FD 身份、15 分钟以内窗口、未撤销状态及首笔操作和隔离根的逐字段绑定。`BEGIN IMMEDIATE` 事务检查前后重复观察，期间删除、轮换、撤销或不匹配一律拒绝。测试涵盖错误执行、计划、操作和文件名符号链接、模式权限及竞争条件。
- **不能把该证据解释成真实 host approval**：任意本地 JSON 的内容仍不具备可信授权来源、不可伪造性或执行时锁定。两次相同也只返回 `HOST_EVIDENCE_ONLY_NO_GRANT`，永久 `host_approval_obtained=false`、`writes_authorized=false`、不记录 journal、不联系 Transmission。真实受控写入仍需独立主机策略与原子执行期机制，此候选未启用生产 Worker 对验收执行的写入。

## 下一阶段仍需独立实现和验收

这一阶段优先解决“未通过验收不能启用、不能启用又无法验收”的只读入口循环。它不声明真实下载器操作已获执行环境许可，也不会清除冲突或人工对账 journal。完成任务匹配及源文件内容的同一 execution 证据后，仍需要逐项开发并检验严格受控的**真实写入门禁**，取得目标目录及外部 ADD/RECHECK/START 的成功证据，才可考虑把 CarPT 记为真实完整 E2E 已验收。绝不可直接改写上述冻结标记/Registry/数据库 enabled 字段来绕开限制。
