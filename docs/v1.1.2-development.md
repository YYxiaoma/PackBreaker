### 限流 Retry-After 与自动重试冷却保护（独立候选）

在 [PR #11](https://github.com/YYxiaoma/PackBreaker/pull/11) 修复永久性错误重试及超时误分类之后，继续发现匹配协调器**丢弃了底层站点适配器返回的 `retry_after_seconds`**：当 Tracker 反馈正常的限流冷却时间时，任务级重试仍会在默认短间隔后重新搜索，可能过早请求临时限制中的站点。

本轮独立候选 [PR #12](https://github.com/YYxiaoma/PackBreaker/pull/12) 将可重试错误的站点冷却提示传递给任务级退避，选取**默认指数等待和有效 `Retry-After` 中较长者**。无法安全解析、非有限、负数、超过 24 小时的冷却值不会进入自动重试；转为带原始错误码的人工处理，避免无限等待、日期溢出或过早重复访问。

隔离负向测试在修复前确认 120 秒被误安排为约 2 秒，以及 `NaN`、`Infinity`、负数、超长值均不受控；修复后全部通过，并通过匹配、站点可靠性及 unpack v2 相关单元回归。尚需针对**此 PR 的最终精确源码 SHA**完成 CI、原生 ARM64、浏览器和真实 Docker 门禁。该修复不取种、不启用新站点、不访问生产下载器或 NAS，不替代站点实际权限及内容校验。

### 2026-10-10 M-Team HTTP-date 限流冷却兼容修复（已合并）

M-Team API 的 HTTP 429 可能携带符合 HTTP 规范的日期形式 `Retry-After`，但旧解析器仅识别数字秒数，日期值会被降格为 `None`，导致现有任务级退避策略（PR #12）收不到站点要求的冷却时间。针对性 MockTransport 测试先于修复确证这一缺口。

[PR #13](https://github.com/YYxiaoma/PackBreaker/pull/13) 将两种格式（数字秒数 / 带时区 HTTP-date）转换为安全的等待秒数。缺失响应头时仍使用默认退避；无法解析的日期、非有限/负数/超过 24 小时的明确等待值则**拒绝自动短间隔重试**，交由已实现的安全失败关闭机制处理。全部使用合成 HTTP 429 响应，不访问真实站点或下载器，不输出鉴权材料。

修复前对应新增用例六项失败，修复后全绿；站点可靠性、适配器、拆包匹配和候选分页范围 202 项回归通过，Ruff 静态和格式检查通过。PR #13 已通过精确 SHA 的 Push/PR CI、原生 ARM64 及 Candidate Docker E2E 后合并（`ce4ae51`）。真实站点独立取种、Piece Hash、Tracker 根因和完整辅种未因此解除门禁。

### 2026-10-10 Rousi Pro / NexusPHP 只读恢复与限流统一（PR #14 已合并）

- Rousi Pro 的**只读认证/公开搜索 GET** 在 HTTP 429、HTTP 5xx 或网络连接失败时，原实现将临时故障错误归类为不可重试或一般 HTTP 错误。候选将这些故障保留为可受限退避的 `SITE_RATE_LIMITED` / `SITE_UNAVAILABLE`，同时保持认证失败、非 5xx 的无效请求不可重试。
- Rousi Pro 与 NexusPHP 的 429 现在都会保留有效数字秒数或 HTTP-date 形式的 `Retry-After`。M-Team、Rousi、NexusPHP 共享一个解析器，避免分站点发生冷却口径漂移；异常日期、非有限或超长等待值由原有安全门拒绝自动短间隔重试。
- Rousi Torrent 下载（包括服务器 503）继续由站点可靠性层 `retry_allowed=False` 保证**不会立即重放一次性取种请求**；其原有失败状态元信息不变。
- 全部只使用 MockTransport、隔离单元测试与既有合成媒体，未访问真实站点、未下载 torrent、未操作生产下载器或 NAS；完整业务 E2E、真实站点独立 Piece Hash 与 Tracker 故障根因仍需另行验收。PR #14 的精确最终源码 SHA `340408e5e269ee5ea5a7330a42a53941a53ed09d` 已通过 Push CI、PR CI、原生 ARM64、浏览器及 Candidate Docker E2E 并合并为 `40fe44c684963f5f10a9ab17bea5d29d9252b513`。
