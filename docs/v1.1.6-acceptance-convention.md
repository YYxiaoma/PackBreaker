# PackBreaker v1.1.6 人工验收约定

## 目标

人工验收实例中的数据拆包必须具备与真实生产环境一致的业务执行权限和后台推进能力。不得为了验收而人为降低执行阶段权限、暂停后台任务，或限制任务可发现的影片数量。

## 数据拆包执行要求

1. **影片发现**：按正常生产逻辑扫描所选来源目录及其子目录；不得设置人工验收专用的总影片数上限、目录深度上限或提前截断条件。分页批次仅用于控制单次工作量，必须通过游标持续推进，直至扫描完成。
2. **站点匹配**：正常执行自动匹配、候选生成、人工审核、失败重试及匹配终态汇总，不得暂停在匹配阶段。
3. **内容验证**：正常执行内容与种子文件验证。
4. **辅助文件**：正常执行辅助文件获取、校验与补齐。
5. **执行计划**：正常执行路径、冲突、权限、文件快照及风险检查；需要审批的高风险操作仍按生产规则审批。
6. **媒体落位**：允许按任务配置执行真实文件操作，包括复制、硬链接或其他已支持的存放方式。
7. **下载器辅种**：允许按任务配置执行真实下载器 ADD、RECHECK/VERIFY、START 等操作，并完成状态回读与对账。新增任务第二步的「跳过下载器检查」开关默认关闭；开启时仅在 PackBreaker 已完成 FULL_VERIFIED 内容验证后生效。QB 仅在当前 API 支持且存放方式满足安全条件时使用原生 `skip_checking`，否则自动回退正常校验；Transmission 不支持单任务原生跳检，仅跳过 PackBreaker 主动发起的额外 VERIFY，仍等待/确认 Transmission 自身检查与最终做种状态。任何情况下均不得跳过 Hash、保存路径、归属、文件及最终对账检查。
8. **后台调度**：发现、匹配、验证、辅助文件、执行计划、媒体落位和辅种各阶段均由正常 `UnpackDriver` 推进，不得通过 monkey patch、替换 `UnpackDriver.start`、测试专用暂停开关或人工验收环境变量关闭工作线程。

## 权限与安全边界

- v1.1.6 人工验收任务使用普通生产任务执行快照，不得被自动标记为只读验收任务或写入受限的 acceptance mode。
- 不得删除或绕过生产业务安全机制：授权路径范围、源文件快照校验、冲突检查、完整内容校验、幂等 Journal、下载器路径映射校验和高风险操作审批仍然有效；站点声明的最小请求间隔、限速及风控冷却也必须遵守，它们属于站点约束而非人工验收限制。
- 人工验收实例应使用正式应用启动入口及正常后台调度配置；禁止使用仅提供 API、但人为屏蔽后台 Driver 的特殊启动命令。
- 发现阶段批次、匹配批次和各执行阶段批次是吞吐控制参数，不是任务总量限制。除非有明确的资源保护原因，不得将它们配置为导致任务无法持续推进的值。

## 当前实例约定

- 后续代码改动继续在 PackBreaker 主工作区 `v1.1.6` 分支进行。
- 使用当前已配置 CookieCloud、站点和 QB/TR 下载器的实例，不创建替代实例。
- 保留现有站点配置、下载器配置、数据库和媒体目录；重启时使用正常生产入口，不注入 `hold_unpack_worker` 等暂停补丁。
- 已有验收任务保持普通任务执行快照；终态异常子项必须按后端 `retry_capability` 判断安全恢复方式，不得因重启 Driver 自动重置任务、清空操作日志或重复执行外部操作。
- 本约定不代表发布 v1.1.6，也不授权修改发布标签或推送正式镜像。
