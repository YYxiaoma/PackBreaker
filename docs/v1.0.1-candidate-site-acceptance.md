## 候选镜像身份（不是正式发布）

- 历史候选提交 `47ec58c30ad521ebf00b2646d544556715d275b3`、原测试标签 `candidate-v1.0.1-47ec58c` 仅是旧验收记录，**不代表当前候选分支的源码身份**，禁止用其旧镜像代替本轮候选验收。
- 当前独立交付流程 `Candidate Image Delivery` **只能手动触发**：先将经审查的完整候选源码提交推送到 `candidate/v1.0.1`，确认该提交对应的 `CI`（包含原生 ARM64）与 `Candidate Docker E2E` 两条工作流均通过；在 GitHub Actions 选择候选分支并输入该提交完整 40 位小写 SHA。工作流拒绝非法 SHA、非候选分支提交和项目版本不符的提交，不会因普通代码推送自动上传候选镜像。
- **流程启用前置条件：** GitHub 要求 `workflow_dispatch` 工作流文件已经存在于仓库默认分支。若 `main` 仍是旧版仅支持 `push` 的文件，候选分支上的本次改动不会自动令「Run workflow」出现；须先经过独立审查，将**仅该工作流的受控手动触发配置**合入默认分支，再选择 `candidate/v1.0.1` 与已通过 CI 的精确提交来运行。不得为绕过这项限制而放宽镜像正式发布门禁或临时改成所有候选推送自动交付。
- GHCR 测试标签按指定提交生成 `ghcr.io/yyxiaoma/packbreaker:candidate-v1.0.1-<提交前 12 位>`；如果标签已存在则拒绝覆盖。构建只检出输入的候选分支历史提交，不能从当前工作区、旧固定 SHA 或 `latest` 偷换源码。
- 工作流推送后核对两个真实平台的 manifest、配置版本/提交，并在独立临时配置下验证 AMD64 与原生 ARM64 同一 index digest 的容器运行。只有所有步骤成功，才把工作流输出的完整 `image@sha256:<index-digest>` 用于测试部署。
- 不创建正式 Git Tag、GitHub Release 或发布资产；不移动 `1.0.0`、`1.0.1`、`stable`、`latest`。候选标签仅用于测试，部署时使用不可变摘要。

## 在 Synology 上创建**独立**测试实例

在 Synology 上选择与正式容器不同的容器名和主机端口，并新建两个**空的、专属于候选**的配置/数据目录。不要挂载正式 `/config`、已有数据库、旧 SecretStore、下载器、真实媒体或 Docker socket；不要复制整套正式数据库。先确保新目录仅测试容器可写且满足容器运行用户的权限要求。

使用以下独立 Compose 模板（变量中的路径和摘要应在 Synology 本地配置；不要把凭据写在 Compose 或发送到聊天中）：

```yaml
services:
  packbreaker-candidate:
    image: ${PB_CANDIDATE_IMAGE:?必须填写候选镜像完整不可变摘要}
    container_name: packbreaker-candidate
    restart: unless-stopped
    user: "${PB_CANDIDATE_UID:-1000}:${PB_CANDIDATE_GID:-1000}"
    ports:
      - "${PB_CANDIDATE_BIND_IP:-127.0.0.1}:18091:8000"
    environment:
      PACKBREAKER_TIMEZONE: Asia/Shanghai
    volumes:
      - ${PB_CANDIDATE_CONFIG:?必须填写全新隔离配置目录}:/config
      - ${PB_CANDIDATE_DATA:?必须填写全新隔离数据目录}:/data
```

默认仅绑定宿主机回环地址；如果要从自己的电脑在受信任局域网中打开，请在 Synology 本地将 `PB_CANDIDATE_BIND_IP` 改为专用管理网卡地址，并用防火墙限制来源。不要将测试管理端直接暴露到互联网。若 GHCR 不可达或包没有公开读取权限，先处理镜像可达性；不能自动退回 `latest` 或旧正式镜像。**候选工作流成功之前，不应启动上面的部署命令。**

## 当前受控站点验收范围

1. 在候选实例中初始化独立管理员账号。正式支持的 M-TEAM、HHClub、HDTime 仅在已获授权的受控实例中执行必要的只读连接测试；不得将 Cookie、API Key 或管理员密码复制到聊天、日志或 Git。
2. v1.0.1 已取消「站点详情／用户资料」入口，此前关于六项账号指标及「复制脱敏验收结果」的历史验收流程**不再适用于当前版本**，不得因入口已删除而宣称这些统计字段通过验收。
3. 新增八站仍标记为 `PENDING_ADAPTER`。独立候选容器启动或单次真实 Torrent 元信息读取，不等于可以在正式 UI 保存、启用或执行生产辅种任务；逐站真实任务需经过单独授权与风险隔离，不在本文件的默认只读验收范围内。
4. 清理测试实例时，只删除此次新建的候选容器及专属目录；不得删除、重命名、升级或重建正式 PackBreaker 容器与挂载。

验收结论须区分：指定提交的 CI 通过、双架构候选镜像与原生运行通过、独立候选服务启动通过、正式三站只读连接测试通过及新增八站各自受控真实任务证据。前四者不能替代最后一项；未经真实任务验收的站点不可解除正式门禁。
