# PackBreaker v1.1.4 候选交付工作流

## 目的与范围

本变更只增加 v1.1.4 候选镜像的受控交付工作流、对应回归测试和本说明。它不修改正式发布基线，不合并 v1.1.4 功能开发，不触发镜像构建或发布。

## 交付前置条件

1. v1.1.4 源码已提交到 `candidate/v1.1.4`，且该分支 HEAD 与输入的完整 40 位提交 SHA 完全一致。
2. 同一 SHA、同一候选分支的 `ci.yml` 与 `candidate-docker-e2e.yml` 均存在已完成且成功的 push 运行。
3. 源码版本字段必须为 1.1.4。
4. 仓库已配置 `DOCKERHUB_USERNAME` 和 `DOCKERHUB_TOKEN` Secrets；GHCR 使用工作流的最小权限 GITHUB_TOKEN。

## 正式升级基线

当前已发布基线仍为 v1.1.2，基线提交为 `970cbdd199cf4f9e459ccf76bf23c982d2fa16e6`，不可变镜像摘要为 `sha256:e2d3963ce0eaabc1e323180bab3e3f6274151b9bf8fa97d2e61aa992dc59a153`，Alembic revision 为 `0045_seven_site_capacity_v111`，平台为 linux/amd64 与 linux/arm64。该信息与当前 `release-baseline.json` 一致，所以本 PR 不更改基线文件。

## 候选交付行为

- 只允许在 `main` 上手动调度候选交付工作流，并显式输入已审查的候选 SHA。
- 只生成 `candidate-v1.1.4-<SHA 前 12 位>` 候选标签，分别推送到 GHCR 与 Docker Hub。
- 推送前拒绝覆盖任一仓库中已经存在的同名候选标签。
- 验证两个 registry 的多架构 manifest 摘要一致，并验证 AMD64 与原生 ARM64 运行时身份。
- 不创建正式 Git tag 或 GitHub Release，不更新 `latest` 或 `stable`。

## 授权边界

此 PR 只供审查。创建候选源码分支、确认 SHA 绑定 CI 证据，以及手动调度工作流实际推送候选镜像，均是独立步骤。当前 PR 不执行这些步骤；正式发布仍需另行授权。
