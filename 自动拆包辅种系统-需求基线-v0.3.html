项目需求基线 v0.3安全增强版

自动拆包辅种系统

以“大包”下载任务为输入，自动识别单影片/单集单元，跨 PT 站搜索候选，在内容完整性验证通过后，通过硬链接安全复用已有数据完成多站辅种；覆盖预演、人工确认、失败恢复、历史辅种和剧集拆包。

〇、v0.3 变更摘要（2026-09-05）

变更项相对 v0.2 的调整
辅种安全门新增内容完整性验证等级；只有本地完整 piece 校验通过的任务才允许 qBittorrent 跳过校验。
源数据保护源数据默认只读；硬链接目标需要修复写入时，必须先复制为独立 inode，禁止通过硬链接修改原始大包。
缺失文件处理取消图片/NFO“占位”方案；只能复用字节完全一致的本地文件，或由下载器补齐对应 piece。
执行预演在创建链接或添加下载器任务前生成执行计划，展示文件映射、验证等级、风险和预计下载量。
可靠性闭环补充任务幂等、操作日志、失败回滚、取消语义、启动对账和应用创建资源的安全清理。
接入安全补充凭证加密与脱敏、Webhook 签名防重放、站点限流/熔断/缓存及路径穿越防护。
协议兼容明确 BitTorrent v1、v2、hybrid、padding 文件、零长度文件及跨文件边界 piece 的处理要求。
v0.3 继承 v0.2 已确认范围，并将“零误辅种、源数据不可损坏、任务可恢复”提升为 v1.0 的强制验收目标。

一、范围与产品原则

  • 形态：本期为独立平台，不开发 MoviePilot 插件；预留下载完成事件 Webhook/API。
  • 环境：v1.0 面向 linux/amd64 单机自用场景；arm64、armv7 后续迭代。
  • 下载器：支持多个 qBittorrent / Transmission 实例，以分类或标签命中“大包”作为自动触发条件。
  • 站点：首批 M-Team、HDTime、HHClub；通过统一适配器逐步扩展其他站点。
  • 安全默认值：自动化、跳过校验、写入修复和 docker.sock 均采用显式启用；不满足安全门时自动阻断。
  • 数据原则：源任务数据只读；系统不得因匹配、硬链接、校验、修复或清理改变源文件内容。

模块功能要点

2. PT 站接入统一 SiteAdapter、凭证管理、搜索与取种、超时重试、速率限制、缓存、熔断、健康状态和自动化开关。

4. 安全执行预演计划、人工确认、安全路径、硬链接创建、源数据写保护、添加下载器、安全门和结果确认。
5. 修复与恢复99% 修复三种模式、缺失文件补齐、失败重试、幂等去重、取消回滚、启动对账和孤立资源清理。

7. 系统能力任务中心、配置中心、通知、审计日志、备份恢复、健康检查、界面升级和对外集成接口。

三、核心工作流

1
触发与去重
轮询、手动或 Webhook 触发；按源下载器、源 hash 和处理类型生成幂等键，已有活跃/成功任务时不重复创建。
2
源任务就绪检查
确认下载完成、非移动状态、文件大小与路径在稳定期内不再变化，并验证容器与下载器路径映射。
3
大包解析
读取 torrent 文件列表与本地目录，识别片名、年份、版本、季集和媒体文件，将大包拆分为可独立匹配的单元。
4
站点搜索
对每个单元搜索启用站点；无结果时按保守的 token 组合兜底搜索，使用站点级限流、缓存、重试和熔断。
5
候选匹配
先用名称、ID、大小、版本和文件结构排序，再下载候选 torrent，建立本地源文件到候选路径的逐文件映射。
6
完整性验证
按候选 torrent 的 piece 规则读取映射数据并校验；无法证明完整一致时标记为需要下载器完整校验或阻断。
7
预演与确认
展示匹配证据、目标结构、冲突、验证等级、硬链接/复制动作、预计补齐量与风险；按规则自动批准或进入人工确认。
8
安全准备数据
校验目标路径、挂载点、权限和可用空间，按候选结构创建目录和硬链接，并为每个资源登记所有权。
9
添加与校验
qB 仅对 FULL_VERIFIED 任务允许跳过校验；其他任务以暂停状态添加后完整校验。TR 始终执行客户端校验。
10
确认、修复与收尾
100% 做种后完成并通知；不完整时进入安全修复；失败或取消时根据操作日志回滚系统创建的资源，并保留诊断证据。

四、内容验证与匹配规则

4.1 两阶段匹配

  1. 候选排序：片名、年份、IMDb/豆瓣 ID、季集、分辨率、片源、编码、音轨、制作组、总大小和文件名相似度。
  2. 硬约束：候选 torrent 可解析、文件映射无歧义、目标路径安全、文件长度兼容；任一硬约束不满足不得自动执行。
  3. 内容验证：使用候选 torrent 的 piece length、文件顺序和 piece hash 校验实际本地字节，正确处理跨文件边界 piece。
  4. Info-hash：相同 Info-hash 是强证据；跨站种子可能因 private/source 等字段产生不同 Info-hash，不能据此否定相同内容。
  5. 抽样验证：只可用于候选排序和风险提示，不得作为跳过完整校验的依据。

4.2 验证等级

等级定义与后续动作
FULL_VERIFIED所有候选 piece 均由本地映射数据验证通过；qB 可按配置跳过客户端校验。
CLIENT_CHECK_REQUIRED文件映射可信但未完成全部本地 piece 校验；以暂停状态添加，由下载器完整校验后决定是否做种或补齐。
BLOCKED存在缺失/歧义映射、不安全路径、跨文件系统限制或其他高风险；不得自动创建链接和添加任务。

4.3 Torrent 兼容

解析器必须识别 BitTorrent v1、v2 与 hybrid torrent，正确处理 padding 文件、零长度文件、UTF-8/Unicode 路径、大小写敏感差异和多文件 torrent。暂不支持的格式进入人工队列，不得降级为未验证自动辅种。

五、硬链接与修复安全

  • 目标目录严格复现候选 torrent 的安全相对路径；拒绝绝对路径、..、NUL 字符、越过目标根目录及文件/目录冲突。
  • 创建硬链接前检查源与目标设备 ID、源文件类型、权限、空间和现有目标；跨文件系统时阻断，不静默复制整个媒体文件。
  • 每个目录、链接、复制文件和下载器任务写入操作日志；清理功能只处理由本系统创建且仍符合登记信息的资源。
  • 源数据默认只读。任何可能写入媒体文件的修复，必须先把目标硬链接复制并原子替换为独立 inode，再允许下载器写入。
  • 缺失图片、NFO、字幕等只能复用内容完全一致的文件或下载对应 piece；禁止创建占位文件冒充完成。
  • piece 跨越多个文件时，修复前必须识别全部受影响文件；无法隔离所有硬链接写入风险时转人工处理。
系统在任何自动流程中都不得写入、截断、重命名或删除源任务文件。源数据内容发生变化视为阻断发布的严重缺陷。

99% 修复模式

  1. 自动 piece 修复：仅在映射明确、影响范围可隔离时执行；先解除目标硬链接，再补齐并重校验。
  2. 仅文件级修复：只处理缺失的独立文件或可安全复制的完整文件，不修改硬链接媒体。
  3. 人工引导：生成缺失 piece、关联文件、来源路径和建议命令，等待用户确认。

六、站点与下载器适配

SiteAdapter 统一接口：test_connection()、search(query)、fetch_details(id)、fetch_torrent(id)、capabilities()。核心引擎不得依赖具体站点响应结构。

站点接入方式鉴权v1.0 状态
M-Team官方开放 API：搜索、详情与下载令牌API Key首批，已核实
HDTimeNexusPHP 网页搜索与下载接口passkey，可选 cookie首批，已核实
HHClub研发阶段确认引擎后实现待确认首批，待确认
  • 每站独立配置超时、重试、并发和请求间隔；重试采用带抖动的指数退避，并识别限流响应。
  • 搜索结果按站点和查询条件短期缓存；连续鉴权失败、限流或服务错误时熔断，并发送一次聚合通知。
  • 站点必须同时启用“站点可用”和“允许自动化”才参与任务，默认关闭自动化。
  • 下载器适配器统一提供连接测试、任务查询、文件列表、添加、校验、暂停、恢复与删除系统任务能力，并通过 capabilities 声明差异。

七、任务状态、幂等与恢复

主状态：PENDING → ANALYZING → SEARCHING → MATCHING → PREFLIGHT → VERIFYING → LINKING → ADDING → CLIENT_VERIFYING → SEEDING → DONE。

分支状态：AWAITING_CONFIRMATION、PAUSED、RETRY、FAILED、CANCELLING、ROLLING_BACK、CANCELLED。

  • 任务级幂等键覆盖源下载器、源 hash、处理单元和任务类型；候选执行级幂等键额外包含站点、候选种子 ID 和目标下载器。
  • 每一步先记录意图，再执行外部动作，最后记录结果；重试前检查文件系统和下载器真实状态。
  • 进程启动时执行对账：恢复可继续任务、确认已添加种子、补记已创建链接，并标记无法判定的任务等待人工处理。
  • 重复触发、Webhook 重放和进程崩溃不得导致重复下载器任务、重复硬链接或状态倒退。
  • 取消默认停止后续动作并回滚本系统创建的未使用资源；已开始做种的任务需二次确认后才从下载器移除。

八、技术选型与部署

后端：Python 3.11 + FastAPI + SQLAlchemy + Alembic + SQLite(WAL) + APScheduler；进程内 asyncio 队列配合数据库状态机。

前端：Vue 3 + Vite + Element Plus + Pinia + Axios + ECharts；FastAPI 托管前端 dist。

镜像：buildx 多阶段单镜像，v1.0 发布 linux/amd64；/config 保存数据库、配置和日志，/data 映射媒体与硬链接目录。

  • 启动时运行 Alembic 迁移；升级前备份数据库并校验备份可读，健康检查失败时回滚旧镜像和数据库。
  • 升级中心通过可选 docker.sock 拉取并重建容器；默认不挂载，部署界面明确其等同 Docker 管理权限。
  • 提供数据库、非敏感配置和加密凭证的备份恢复；包含凭证的导出包必须再次加密。
  • 健康检查区分存活、就绪、数据库可写、下载器连通和站点状态，外部依赖异常不应导致容器反复重启。

九、认证、凭证与外部接口

  • 界面采用单管理员访问口令；口令只保存强哈希，登录会话具备过期、注销、登录失败限速和 CSRF 防护。
  • 站点、下载器和通知凭证必须加密落盘；主密钥来自环境变量或权限为 0600 的独立文件，不写入数据库和日志。
  • 界面默认脱敏展示凭证；测试连接、异常堆栈、日志导出和通知内容不得包含 API Key、passkey、Cookie、Token 或密码。
  • 下载完成 Webhook 使用 HMAC-SHA256 签名、时间戳、随机值与幂等键；拒绝过期请求、重复请求和签名失败请求。
  • 轻量 API 覆盖任务创建、查询、取消和人工确认；所有写操作记录操作者、时间、参数摘要与 trace_id。

十、界面、日志与运维

页面：仪表盘、任务中心、预演/人工确认、站点管理、下载器与路径诊断、规则配置、历史辅种、清理与对账、系统设置、升级中心、日志。

任务详情：显示状态时间线、候选评分证据、逐文件映射、piece 验证进度、验证等级、操作资源、重试记录和失败原因；支持导出脱敏诊断包。

日志：DEBUG/INFO/WARN/ERROR 分级和大小+时间轮转；trace_id 贯穿站点、匹配、文件系统和下载器操作；支持级别、关键字、时间与任务过滤。

通知：v1.0 实现 Server酱与 Telegram；按任务聚合重复错误，通知包含结果摘要与任务链接，不包含敏感字段。

交互：中文本地化、响应式布局、深浅主题；危险操作展示确切影响范围，并要求二次确认。

十二、v1.0 验收标准

场景验收要求
误辅种防护真实验收语料中自动执行误辅种为 0；任一 piece 不匹配时不得标记 FULL_VERIFIED 或跳过校验。
源数据保护正确、错误和中断修复场景执行前后，所有源文件内容 hash 与 inode 均保持不变。
幂等相同事件连续触发 10 次，只产生一个有效任务、一个目标资源集合和一个下载器任务。
崩溃恢复在 LINKING、ADDING、CLIENT_VERIFYING 阶段强制终止进程，重启后能继续或进入可解释的人工状态，无重复副作用。
路径安全跨文件系统、错误映射、路径穿越、权限不足和目标冲突均在外部写操作前阻断。
协议兼容合成语料覆盖 v1、v2、hybrid、多文件、padding、零长度文件和跨文件 piece。
凭证安全数据库、普通配置导出、日志、通知和诊断包中不出现可直接使用的明文凭证。
主链路qBittorrent 与 Transmission 分别完成至少一条真实语料端到端辅种，并覆盖人工确认和失败回滚。
