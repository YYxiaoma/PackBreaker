项目需求基线 v0.2已确认版

自动拆包辅种系统

以「大包」下载任务为输入，自动拆解为单影片/单集单元，跨 PT 站搜索匹配同名资源，通过硬链接复用已有数据完成多站辅种；附带失败修复、历史影片重新做种、剧集拆包能力。独立部署平台，支持 qBittorrent / Transmission 与多 PT 站。

〇、需求确认记录（2026-09-05 · 10 项全部确认）

9使用规模单机自用。架构简化：SQLite(WAL)、单进程部署、不做多用户与租户权限；界面仅需内网访问口令。
10界面化升级需要。内置升级中心：检查版本 → 界面点击 → 经可选挂载的 docker.sock 拉新镜像重建容器 → 健康检查通过后完成、失败回滚；docker.sock 需用户知情授权（部署时说明）。
以上 10 项构成 v0.2 基线。后续新增/变更需求需重新评估影响并升级版本号。

二、核心工作流（拆包辅种主链路）

1
监控触发
轮询 qB/TR，命中 分类/标签含「大包」且任务完成 → 生成拆包任务（可手动触发/接口触发）
2
大包解析
读取种子文件列表，按命名规则识别影片单元（片名/年份/分辨率/季集编号），单元化拆分
3
站点搜索
对每个单元用完整名称搜索已选站点；无结果 → 兜底分段搜索；有结果 → 多维匹配
4
多维匹配
大小 / 文件列表 / 命名 token / Info-hash（拉种后）/ IMDb 等多维评分；唯一命中 → 继续；多候选难判 → 人工确认队列；未命中 → 记录跳过
5
硬链接准备
按候选种子文件结构自动建目录，从大包硬链接；文件名/路径不一致时重命名归一（硬链接改名不影响原种做种）；跨文件系统自动检测拦截
6
添加辅种
qB：添加种子 + 跳过校验；TR：定位本地数据后校验（无跳过校验特性）
7
状态确认与修复
100% 做种 → 完成 + 通知；卡 99% → 按用户选择模式修复（补 piece/仅文件级/人工引导）；缺图/nfo → 补齐或占位

三、站点接入规划（新增 · 已核实）

分层架构：拆包辅种引擎只依赖统一接口 SiteAdapter（search(keywords)、fetch_torrent(id)、鉴权封装），具体站点差异收敛到「引擎适配器」，新增站点 = 新增配置项或适配器，不动核心引擎。

站点接入方式鉴权状态
M-Team（馒头）官方开放 API：api.m-team.cc / api.m-team.io，/api/torrent/search、genDlToken 等API Key（x-api-key，控制台「实验室」生成）首批 · 已核实
HDTimeNexusPHP 网页接口：torrents.php?search= + download.phppasskey（+可选 cookie）首批 · 已核实
HHClub疑似 NexusPHP 系，研发阶段确认后按实际引擎实现待确认首批 · 待确认
其他站点Gazelle / UNIT3D / 官方 API / 其他 NexusPHP 变体按引擎后续迭代补全
每站点独立配置：超时、重试次数、搜索间隔（站点风控差异大）；所有自动化操作遵守各站规则，提供「允许自动化」站点级开关，默认保守。

四、匹配算法维度（补全）

  1. Info-hash 精确比对：下载候选 .torrent 后比对，同种即确定命中（最高权重）
  2. 总大小比对：±1%~5% 容差可配置
  3. 文件列表比对：文件数 + 文件名相似度（编辑距离/Jaccard）
  4. 命名解析 token：片名、年份、分辨率(1080p/4K)、片源(BluRay/WEB-DL/REMUX)、编码(H.264/HEVC/x265)、音轨(Atmos/DTS-HD)、制作组、季/集编号
  5. IMDb/豆瓣 ID：详情页可取时比对
  6. 样本文件比对（可选）：sample 时长/内容一致性
  7. 综合评分：加权得分高于阈值自动命中；低于阈值进人工确认队列
兜底搜索：去除年份/分辨率/版本等关键词后按 token 组合重新搜索，必须设严格阈值防止误配。

最终组合：后端 Python 3.11 + FastAPI + SQLAlchemy(Alembic) + SQLite(WAL) + APScheduler；前端 Vue3 + Vite + Element Plus + Pinia + Axios + ECharts；单镜像（FastAPI 托管前端 dist）。

任务执行：进程内 asyncio 任务队列 + 数据库持久化任务状态机（PENDING→SEARCHING→MATCHING→LINKING→ADDING→VERIFYING→SEEDING→DONE/FAILED/RETRY/PAUSED），重启可恢复。

单机部署：不引入多用户/租户体系；界面仅内网访问口令保护。

六、Docker 部署与升级兼容

  • 平台：v1.0 出 linux/amd64；buildx 多阶段、平台参数化，arm64/armv7 预留后续构建
  • 数据卷分离：/config（配置+SQLite+日志）、/data（硬链接/媒体目录映射，需与下载器同一底层文件系统）
  • 数据兼容：schema 版本号与镜像版本绑定，启动前置迁移脚本（Alembic）；升级前自动备份 DB
  • 界面一键升级（已确认需要）：升级中心 → 检查新版本（GitHub Releases/镜像 tag）→ 界面点击 → 经可选挂载的 docker.sock 拉新镜像重建容器 → 健康检查通过后完成，失败自动回滚旧 tag
  • 安全提示：docker.sock 挂载为可选项，部署向导中明示风险并由用户确认

七、插件 vs 独立平台（已确认：独立平台为主）

  • 本期不做 MoviePilot 插件；独立平台完整承载任务队列/调度/修复/通知/UI
  • 预留集成位：下载器完成事件对外 webhook + 轻量 API，后续做 MP 插件时直接复用（Python 栈已保证可行性）

八、日志与界面设计

日志体系：分级 DEBUG/INFO/WARN/ERROR；滚动轮转（按大小+时间）；每任务 trace_id 贯穿搜索/匹配/硬链接/添加全链路；界面日志查看器（级别/关键字/时间过滤、按任务关联）；支持导出。

界面页面清单：①仪表盘（站点健康/下载器状态/今日任务/成功率/做种统计）②任务中心（列表+详情时间线+重试/取消/人工确认）③站点管理 ④下载器管理 ⑤规则配置（匹配阈值/硬链接策略/修复策略三选一/兜底策略）⑥历史辅种（扫描路径+文件类型配置）⑦系统设置（通知渠道 Server酱/Telegram、调度、升级中心）⑧日志页。中文本地化、响应式（NAS 手机端可用）、深色/浅色主题。
